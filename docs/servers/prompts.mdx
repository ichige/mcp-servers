Promptは、LLMが構造化された目的のある応答を生成するのに役立つ、再利用可能なメッセージテンプレートです。FastMCPは、主に `@mcp.prompt` Decoratorを使用して、これらのテンプレートの定義を簡素化します。

## Promptとは？

Promptは、LLM向けのパラメータ化されたメッセージテンプレートを提供します。ClientがPromptをリクエストすると、以下の処理が行われます。

1.  FastMCPは対応するPrompt定義を検索します。
2.  パラメータがある場合、関数のシグネチャに対して検証されます。
3.  検証された入力を使用して関数が実行されます。
4.  生成されたメッセージがLLMに返され、その応答をガイドします。

これにより、LLMがさまざまなClientやコンテキスト全体で使用できる、一貫性のある再利用可能なテンプレートを定義できます。

## Prompt

### `@prompt` Decorator

Promptを定義する最も一般的な方法は、Python関数をデコレートすることです。Decoratorは関数名をPromptの識別子として使用します。

```python
from fastmcp import FastMCP
from fastmcp.prompts import Message

mcp = FastMCP(name="PromptServer")

# 文字列を返す基本的なPrompt（自動的にユーザーメッセージに変換されます）
@mcp.prompt
def ask_about_topic(topic: str) -> str:
    """トピックの説明を求めるユーザーメッセージを生成します。"""
    return f"Can you please explain the concept of '{topic}'?"

# 複数のメッセージを返すPrompt
@mcp.prompt
def generate_code_request(language: str, task_description: str) -> list[Message]:
    """コード生成のための会話を生成します。"""
    return [
        Message(f"Write a {language} function that performs the following task: {task_description}"),
        Message("I'll help you write that function.", role="assistant"),
    ]
```

**主要な概念:**

*   **Name:** デフォルトでは、Prompt名は関数名から取得されます。
*   **Parameters:** 関数のパラメータは、Promptの生成に必要な入力を定義します。
*   **Inferred Metadata:** デフォルトの推論されるメタデータ:
    *   Prompt名: 関数名 (`ask_about_topic`) から取得されます。
    *   Promptの説明: 関数のdocstringから取得されます。
<Tip>
`*args` や `**kwargs` を持つ関数は、Promptとしてサポートされていません。この制限は、FastMCPがMCPプロトコル用の完全なパラメータスキーマを生成する必要があり、可変長引数リストではそれが不可能であるためです。
</Tip>

#### DecoratorのArgument

FastMCPは関数から名前と説明を推論しますが、`@mcp.prompt` DecoratorのArgumentを使用してこれらを上書きし、追加のメタデータを付与することができます。

```python
@mcp.prompt(
    name="analyze_data_request",          # カスタムPrompt名
    description="Creates a request to analyze data with specific parameters",  # カスタムの説明
    tags={"analysis", "data"},            # オプションの分類タグ
    meta={"version": "1.1", "author": "data-team"}  # カスタムメタデータ
)
def data_analysis_prompt(
    data_uri: str = Field(description="The URI of the resource containing the data."),
    analysis_type: str = Field(default="summary", description="Type of analysis.")
) -> str:
    """descriptionが提供されている場合、このdocstringは無視されます。"""
    return f"Please perform a '{analysis_type}' analysis on the data found at {data_uri}."
```

#### メソッドでの使用

インスタンスメソッドやクラスメソッドをデコレートする場合は、スタンドアロンの `@prompt` Decoratorを使用し、バインドされたメソッドを登録します。パターンの詳細については、[Tool: メソッドでの使用](/servers/tools#using-with-methods)を参照してください。

### Argumentの型

<VersionBadge version="2.9.0" />

MCPの仕様では、すべてのPromptのArgumentを文字列として渡す必要がありますが、FastMCPでは開発者体験を向上させるために型アノテーションを使用できます。`list[int]` や `dict[str, str]` のような複雑な型を使用する場合、FastMCPは以下の処理を行います。

1. **自動的に変換**: MCP Clientからの文字列のArgumentを、期待される型に自動的に変換します。
2. **役立つ説明を生成**: 必要な正確なJSON文字列フォーマットを示す説明を生成します。
3. **直接の呼び出しを維持**: 適切に型付けされたArgumentを使用してPromptを呼び出すことも可能です。

MCPの仕様では文字列のArgumentのみが許可されているため、Clientは複雑な型に対してどのような文字列フォーマットを使用すべきかを知る必要があります。FastMCPは、Argumentの説明をJSONスキーマ情報で自動的に強化することでこの問題を解決し、人間とLLMの両方にArgumentのフォーマット方法を明確にします。

<CodeGroup>

```python Python Code
@mcp.prompt
def analyze_data(
    numbers: list[int],
    metadata: dict[str, str], 
    threshold: float
) -> str:
    """数値データを分析します。"""
    avg = sum(numbers) / len(numbers)
    return f"Average: {avg}, above threshold: {avg > threshold}"
```

```json Resulting MCP Prompt
{
  "name": "analyze_data",
  "description": "Analyze numerical data.",
  "arguments": [
    {
      "name": "numbers",
      "description": "Provide as a JSON string matching the following schema: {\"items\":{\"type\":\"integer\"},\"type\":\"array\"}",
      "required": true
    },
    {
      "name": "metadata", 
      "description": "Provide as a JSON string matching the following schema: {\"additionalProperties\":{\"type\":\"string\"},\"type\":\"object\"}",
      "required": true
    },
    {
      "name": "threshold",
      "description": "Provide as a JSON string matching the following schema: {\"type\":\"number\"}",
      "required": true
    }
  ]
}
```

</CodeGroup>

**MCP Clientは、文字列のArgumentを使用してこのPromptを呼び出します:**
```json
{
  "numbers": "[1, 2, 3, 4, 5]",
  "metadata": "{\"source\": \"api\", \"version\": \"1.0\"}",
  "threshold": "2.5"
}
```

**しかし、適切な型を使用して直接呼び出すことも可能です:**
```python
# 直接の呼び出しでも機能します
result = await prompt.render({
    "numbers": [1, 2, 3, 4, 5],
    "metadata": {"source": "api", "version": "1.0"}, 
    "threshold": 2.5
})
```

<Warning>
この機能を使用する際は、型アノテーションをシンプルに保ってください。複雑なネストされた型やカスタムクラスは、JSON文字列から確実に変換されない場合があります。自動生成されるスキーマの説明は、期待されるフォーマットについてユーザーが受け取る唯一のガイダンスです。

良い選択: `list[int]`, `dict[str, str]`, `float`, `bool`
避けるべきもの: 複雑なPydanticモデル、深くネストされた構造、カスタムクラス
</Warning>

### 戻り値

Prompt関数は、以下のいずれかのReturn typeを返す必要があります。

-   **`str`**: 単一のユーザーメッセージとして送信されます。
-   **`list[Message | str]`**: メッセージのシーケンス（会話）。文字列は自動的にユーザーのMessageに変換されます。
-   **`PromptResult`**: メッセージ、説明、メタデータを完全に制御します。以下の[PromptResult](#promptresult)を参照してください。

```python
from fastmcp.prompts import Message

@mcp.prompt
def roleplay_scenario(character: str, situation: str) -> list[Message]:
    """初期メッセージを含むロールプレイのシナリオを設定します。"""
    return [
        Message(f"Let's roleplay. You are {character}. The situation is: {situation}"),
        Message("Okay, I understand. I am ready. What happens next?", role="assistant")
    ]
```

#### Message

<VersionBadge version="3.0.0" />

`Message` は、自動シリアライズ機能を備えた、ユーザーフレンドリーなPromptメッセージのラッパーを提供します。

```python
from fastmcp.prompts import Message

# 文字列コンテンツ（デフォルトでuserロール）
Message("Hello, world!")

# 明示的なロール
Message("I can help with that.", role="assistant")

# JSONテキストに自動シリアライズ
Message({"key": "value"})
Message(["item1", "item2"])
```

`Message` は2つのフィールドを受け入れます。

**`content`** - メッセージのコンテンツ。文字列はそのまま渡されます。他の型（dict、list、BaseModel）は自動的にJSONテキストにシリアライズされます。

**`role`** - メッセージのロール。`"user"`（デフォルト）または `"assistant"` のいずれかです。

#### PromptResult

<VersionBadge version="3.0.0" />

`PromptResult` を使用すると、複数のメッセージ、ロール、およびメッセージレベルと結果レベルの両方のメタデータなど、Promptの応答を明示的に制御できます。

```python
from fastmcp import FastMCP
from fastmcp.prompts import PromptResult, Message

mcp = FastMCP(name="PromptServer")

@mcp.prompt
def code_review(code: str) -> PromptResult:
    """メタデータを含むコードレビューのPromptを返します。"""
    return PromptResult(
        messages=[
            Message(f"Please review this code:\n\n```\n{code}\n```"),
            Message("I'll analyze this code for issues.", role="assistant"),
        ],
        description="Code review prompt",
        meta={"review_type": "security", "priority": "high"}
    )
```

単純なケースでは、文字列を直接 `PromptResult` に渡すことができます。

```python
return PromptResult("Please help me with this task")  # 単一のMessageに自動変換されます
```

<Card title="PromptResult">
<ParamField body="messages" type="str | list[Message]" required>
  返すメッセージ。文字列は単一のユーザーMessageとしてラップされます。
</ParamField>
<ParamField body="description" type="str | None">
  Prompt結果のオプションの説明。提供されない場合、デフォルトでPromptのdocstringになります。
</ParamField>
<ParamField body="meta" type="dict[str, Any] | None">
  結果レベルのメタデータで、MCP応答の `_meta` フィールドに含まれます。これを、分類、優先度、またはその他のClient固有のデータなどのランタイムメタデータに使用します。
</ParamField>
</Card>

<Note>
`PromptResult` の `meta` フィールドは、このレンダリング応答に固有のランタイムメタデータ用です。これは、Prompt定義自体に関する静的なメタデータ（Promptのリスト取得時に返される）を提供する `@mcp.prompt(meta={...})` の `meta` パラメータとは異なります。
</Note>

Prompt関数からプレーンな `str` や `list[Message | str]` を返すことも引き続き可能です。`PromptResult` は、メタデータを含める必要がある場合のオプトイン機能です。

### 必須パラメータとオプションパラメータ

関数のシグネチャ内のパラメータは、デフォルト値を持たない限り**必須**と見なされます。

```python
@mcp.prompt
def data_analysis_prompt(
    data_uri: str,                        # 必須 - デフォルト値なし
    analysis_type: str = "summary",       # オプション - デフォルト値あり
    include_charts: bool = False          # オプション - デフォルト値あり
) -> str:
    """特定のパラメータを使用してデータを分析するリクエストを作成します。"""
    prompt = f"Please perform a '{analysis_type}' analysis on the data found at {data_uri}."
    if include_charts:
        prompt += " Include relevant charts and visualizations."
    return prompt
```

この例では、Clientは `data_uri` を提供する*必要があります*。`analysis_type` または `include_charts` が省略された場合、それらのデフォルト値が使用されます。

### コンポーネントの可視性

<VersionBadge version="3.0.0" />

Serverレベルの有効化制御を使用して、Clientに対してどのPromptを有効にするかを制御できます。無効化されたPromptは `list_prompts` に表示されず、呼び出すこともできません。

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.prompt(tags={"public"})
def public_prompt(topic: str) -> str:
    return f"Discuss: {topic}"

@mcp.prompt(tags={"internal"})
def internal_prompt() -> str:
    return "Internal system prompt"

# キーによって特定のPromptを無効化
mcp.disable(keys={"prompt:internal_prompt"})

# タグによってPromptを無効化
mcp.disable(tags={"internal"})

# または許可リストモードを使用 - 特定のタグを持つPromptのみを有効化
mcp.enable(tags={"public"}, only=True)
```

キーのフォーマット、タグベースのフィルタリング、プロバイダーレベルの制御を含む完全な可視性制御APIについては、[可視性](/servers/visibility)を参照してください。

### 非同期Prompt

FastMCPは、標準の関数（`def`）と非同期関数（`async def`）の両方をPromptとしてサポートしています。同期関数は、イベントループのブロックを避けるために自動的にスレッドプールで実行されます。

```python
# 同期Prompt（スレッドプールで実行）
@mcp.prompt
def simple_question(question: str) -> str:
    """LLMに尋ねる簡単な質問を生成します。"""
    return f"Question: {question}"

# 非同期Prompt
@mcp.prompt
async def data_based_prompt(data_id: str) -> str:
    """取得する必要があるデータに基づいてPromptを生成します。"""
    # 実際のシナリオでは、データベースやAPIからデータを取得する場合があります
    async with aiohttp.ClientSession() as session:
        async with session.get(f"https://api.example.com/data/{data_id}") as response:
            data = await response.json()
            return f"Analyze this data: {data['content']}"
```

Prompt関数がネットワークリクエストやデータベースクエリなどのI/O操作を実行する場合は、非同期の方がスレッドプールのディスパッチよりも効率的であるため、`async def` を使用してください。

### MCP Contextへのアクセス

<VersionBadge version="2.2.5" />

Promptは、`Context` オブジェクトを通じて追加のMCP情報や機能にアクセスできます。アクセスするには、Prompt関数に `Context` の型アノテーションを持つパラメータを追加します。

```python {6}
from fastmcp import FastMCP, Context

mcp = FastMCP(name="PromptServer")

@mcp.prompt
async def generate_report_request(report_type: str, ctx: Context) -> str:
    """レポートのリクエストを生成します。"""
    return f"Please create a {report_type} report. Request ID: {ctx.request_id}"
```

Contextオブジェクトとそのすべての機能的の完全なドキュメントについては、[Contextのドキュメント](/servers/context)を参照してください。

### 通知

<VersionBadge version="2.9.1" />

FastMCPは、Promptが追加、有効化、または無効化されたときに、接続されているClientに `notifications/prompts/list_changed` 通知を自動的に送信します。これにより、Clientは変更を手動でポーリングすることなく、現在のPromptセットを最新の状態に保つことができます。

```python
@mcp.prompt
def example_prompt() -> str:
    return "Hello!"

# これらの操作は通知をトリガーします:
mcp.add_prompt(example_prompt)               # prompts/list_changed 通知を送信
mcp.disable(keys={"prompt:example_prompt"})  # prompts/list_changed 通知を送信
mcp.enable(keys={"prompt:example_prompt"})   # prompts/list_changed 通知を送信
```

通知は、これらの操作がアクティブなMCPリクエストコンテキスト内で発生した場合（例: Toolやその他のMCP操作内から呼び出された場合）にのみ送信されます。Serverの初期化中に実行された操作は通知をトリガーしません。

Clientは、[メッセージハンドラー](/clients/notifications)を使用してこれらの通知を処理し、Promptリストを自動的に更新したり、インターフェースを更新したりできます。

## Serverの動作

### 重複するPrompt

<VersionBadge version="2.1.0" />

同じ名前で複数のPromptを登録しようとした場合のFastMCP Serverの処理方法を設定できます。`FastMCP` の初期化時に `on_duplicate_prompts` 設定を使用します。

```python
from fastmcp import FastMCP

mcp = FastMCP(
    name="PromptServer",
    on_duplicate_prompts="error"  # Prompt名が重複している場合はエラーを発生させます
)

@mcp.prompt
def greeting(): return "Hello, how can I help you today?"

# "greeting" はすでに登録されており、動作が "error" に設定されているため、
# この登録試行は ValueError を発生させます。
# @mcp.prompt
# def greeting(): return "Hi there! What can I do for you?"
```

重複時の動作オプションは以下の通りです。

-   `"warn"` (デフォルト): 警告をログに記録し、新しいPromptが古いPromptを置き換えます。
-   `"error"`: `ValueError` を発生させ、重複登録を防ぎます。
-   `"replace"`: 既存のPromptを新しいPromptに静かに置き換えます。
-   `"ignore"`: 元のPromptを保持し、新しい登録試行を無視します。

## バージョニング

<VersionBadge version="3.0.0" />

Promptはバージョニングをサポートしており、同じ名前で複数の実装を維持しながら、Clientが自動的に最も高いバージョンを受け取るようにすることができます。バージョンの比較、取得、および移行パターンの完全なドキュメントについては、[バージョニング](/servers/versioning)を参照してください。
