</Tip>


## MCP バックグラウンドタスクとは？

MCP では、すべてのコンポーネントのインタラクションはデフォルトでブロッキングです。Client が Tool を呼び出したり、Resource を読み取ったり、Prompt を取得したりする際、リクエストを送信してレスポンスを待ちます。数秒から数分かかる操作の場合、これはユーザー体験の低下を招きます。

MCP バックグラウンドタスクプロトコルは、Client に以下の機能を提供することでこの問題を解決します。
1. 操作を**開始**し、即座にタスク ID を受け取る
2. 操作の実行中に進捗を**追跡**する
3. 準備ができたら結果を**取得**する

FastMCP はこれらすべてを自動的に処理します。Decorator に `task=True` を追加するだけで、関数は進捗報告、分散処理、水平スケーリングを備えた完全なバックグラウンド実行が可能になります。

### MCP バックグラウンドタスクと Python の並行処理の比較

FastMCP の Server では、Python の並行処理プリミティブ（asyncio、スレッド、マルチプロセッシング）や外部のタスクキューをいつでも使用できます。FastMCP は単なる Python ですので、好きなようにコードを実行してください。

MCP バックグラウンドタスクは異なります。これらは**プロトコルネイティブ**です。つまり、タスクプロトコルをサポートする MCP Client は、標準の MCP インターフェースを通じて操作を開始し、進捗の更新を受け取り、結果を取得できます。この調整はアプリケーションコード内ではなく、プロトコルレベルで行われます。

## バックグラウンドタスクの有効化

<VersionBadge version="3.0.0" /> バックグラウンドタスクには `tasks` extra が必要です。

```bash
pip install "fastmcp[tasks]"
```

任意の Tool、Resource、リソーステンプレート、または Prompt の Decorator に `task=True` を追加します。これにより、そのコンポーネントがバックグラウンド実行可能としてマークされます。

```python {6}
import asyncio
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.tool(task=True)
async def slow_computation(duration: int) -> str:
    """時間のかかる操作。"""
    for i in range(duration):
        await asyncio.sleep(1)
    return f"Completed in {duration} seconds"
```

Client がバックグラウンド実行をリクエストすると、呼び出しは即座にタスク ID を返します。処理はバックグラウンドワーカーで実行され、Client はステータスをポーリングするか、結果を待つことができます。

<Warning>
バックグラウンドタスクには非同期関数が必要です。同期関数で `task=True` を使用しようとすると、登録時に `ValueError` が発生します。
</Warning>

## 実行モード

タスクの実行動作をきめ細かく制御するには、真偽値の省略記法ではなく `TaskConfig` を使用します。MCP タスクプロトコルでは、3つの実行モードが定義されています。

| Mode | Client calls without task | Client calls with task |
|------|--------------------------|------------------------|
| `"forbidden"` | 同期的に実行される | エラー: タスクはサポートされていません |
| `"optional"` | 同期的に実行される | バックグラウンドタスクとして実行される |
| `"required"` | エラー: タスクが必要です | バックグラウンドタスクとして実行される |

```python
from fastmcp import FastMCP
from fastmcp.server.tasks import TaskConfig

mcp = FastMCP("MyServer")

# 同期実行とバックグラウンド実行の両方をサポート (task=True の場合のデフォルト)
@mcp.tool(task=TaskConfig(mode="optional"))
async def flexible_task() -> str:
    return "Works either way"

# バックグラウンド実行が必須 - Client がタスクをリクエストしない場合はエラー
@mcp.tool(task=TaskConfig(mode="required"))
async def must_be_background() -> str:
    return "Only runs as a background task"

# タスクのサポートなし (task=False または省略時のデフォルト)
@mcp.tool(task=TaskConfig(mode="forbidden"))
async def sync_only() -> str:
    return "Never runs as background task"
```

真偽値のショートカットは以下のモードにマッピングされます。
- `task=True` → `TaskConfig(mode="optional")`
- `task=False` → `TaskConfig(mode="forbidden")`

### ポーリング間隔

<VersionBadge version="2.15.0" />

Client がタスクのステータスをポーリングする際、Server は再確認の頻度を Client に伝えます。デフォルトでは、FastMCP は5秒間隔を提案しますが、コンポーネントごとにカスタマイズできます。

```python
from datetime import timedelta
from fastmcp import FastMCP
from fastmcp.server.tasks import TaskConfig

mcp = FastMCP("MyServer")

# すぐに完了するタスクのために2秒ごとにポーリング
@mcp.tool(task=TaskConfig(mode="optional", poll_interval=timedelta(seconds=2)))
async def quick_task() -> str:
    return "Done quickly"

# 時間のかかるタスクのために30秒ごとにポーリング
@mcp.tool(task=TaskConfig(mode="optional", poll_interval=timedelta(seconds=30)))
async def slow_task() -> str:
    return "Eventually done"
```

間隔を短くすると Client へのフィードバックは早くなりますが、Server の負荷が増加します。間隔を長くすると負荷は減りますが、ステータスの更新が遅れます。

### Server 全体のデフォルト

デフォルトですべてのコンポーネントのバックグラウンドタスクサポートを有効にするには、コンストラクタに `tasks=True` を渡します。個別の Decorator で `task=False` を指定して上書きすることも可能です。

```python
mcp = FastMCP("MyServer", tasks=True)
```

<Warning>
Server に同期的な Tool、Resource、または Prompt が定義されている場合、エラーを避けるためにそれらの Decorator で明示的に `task=False` を設定する必要があります。
</Warning>

### グレースフルデグラデーション

Client がバックグラウンド実行をリクエストしたものの、コンポーネントが `mode="forbidden"` に設定されている場合、FastMCP は同期的に実行し、結果をインラインで返します。これはグレースフルデグラデーションに関する SEP-1686 仕様に従っており、Client は Server の機能を気にすることなく、常にバックグラウンド実行をリクエストできます。

逆に、コンポーネントが `mode="required"` に設定されているのに Client がバックグラウンド実行をリクエストしない場合、FastMCP はタスクの実行が必要であることを示すエラーを返します。

## バックエンド

FastMCP はタスク実行用に2つのバックエンドをサポートしており、それぞれに異なるトレードオフがあります。

### インメモリバックエンド (デフォルト)

インメモリバックエンド (`memory://`) は設定不要で、すぐに使用できます。

**利点:**
- 外部依存関係がない
- シンプルな単一プロセスでのデプロイ

**欠点:**
- **一時的**: Server が再起動すると、保留中のタスクはすべて失われます
- **レイテンシが高い**: タスクのピックアップ時間が約250ミリ秒（Redis の場合は1桁ミリ秒）
- **水平スケーリング不可**: 単一プロセスのみであり、ワーカーを追加することはできません

### Redis バックエンド

本番環境のデプロイでは、`FASTMCP_DOCKET_URL=redis://localhost:6379` を設定して Redis (または Valkey) をバックエンドとして使用します。

**利点:**
- **永続的**: Server が再起動してもタスクは保持されます
- **高速**: タスクのピックアップレイテンシが1桁ミリ秒
- **スケーラブル**: ワーカーを追加して、プロセスやマシン間で負荷を分散できます

## ワーカー

タスクが有効なコンポーネントを持つすべての FastMCP Server は、自動的に**組み込みワーカー**を起動します。タスクを実行するために別のワーカープロセスを起動する必要はありません。

水平スケーリングを行うには、CLI を使用してワーカーを追加します。

```bash
fastmcp tasks worker server.py
```

追加された各ワーカーは同じキューからタスクを取得し、プロセス間で負荷を分散します。ワーカーの並行処理数は環境変数で設定します。

```bash
export FASTMCP_DOCKET_CONCURRENCY=20
fastmcp tasks worker server.py
```

<Note>
追加のワーカーは Redis/Valkey バックエンドでのみ機能します。インメモリバックエンドは単一プロセス専用です。
</Note>

<Warning>
タスクが有効なコンポーネントは、すべてのワーカーに登録されるように Server の起動時に定義されている必要があります。Server 起動後に動的に追加されたコンポーネントは、バックグラウンド実行に利用できません。
</Warning>

## 進捗報告

`Progress` 依存関係を使用すると、Client に進捗を報告できます。デフォルト値を持つパラメータとして注入すると、FastMCP はアクティブな進捗レポーターを提供します。

```python
from fastmcp import FastMCP
from fastmcp.dependencies import Progress

mcp = FastMCP("MyServer")

@mcp.tool(task=True)
async def process_files(files: list[str], progress: Progress = Progress()) -> str:
    await progress.set_total(len(files))

    for file in files:
        await progress.set_message(f"Processing {file}")
        # ... 処理を実行 ...
        await progress.increment()

    return f"Processed {len(files)} files"
```

進捗 API:
- `await progress.set_total(n)` — ステップの総数を設定します
- `await progress.increment(amount=1)` — 進捗をインクリメントします
- `await progress.set_message(text)` — ステータスメッセージを更新します

進捗報告は、即時実行モードとバックグラウンド実行モードの両方で機能します。Client が関数をどのように呼び出すかに関係なく、同じコードを使用できます。

## Docket の依存関係

FastMCP は、タスクが有効な関数内で Docket の完全な依存性注入システムを公開します。`Progress` 以外にも、Docket インスタンスやワーカー情報にアクセスしたり、リトライやタイムアウトなどの高度な機能を使用したりできます。

```python
from docket import Docket, Worker
from fastmcp import FastMCP
from fastmcp.dependencies import Progress, CurrentDocket, CurrentWorker

mcp = FastMCP("MyServer")

@mcp.tool(task=True)
async def my_task(
    progress: Progress = Progress(),
    docket: Docket = CurrentDocket(),
    worker: Worker = CurrentWorker(),
) -> str:
    # 追加のバックグラウンド処理をスケジュール
    await docket.add(another_task, arg1, arg2)

    # ワーカーのメタデータにアクセス
    worker_name = worker.name

    return "Done"
```

`CurrentDocket()` を使用すると、追加のバックグラウンドタスクをスケジュールしたり、処理を連鎖させたり、複雑なワークフローを調整したりできます。リトライポリシー、タイムアウト、カスタム依存関係を含む完全な API については、[Docket のドキュメント](https://chrisguidry.github.io/docket/)を参照してください。", "comment": "ご要求のあったFast MCPのタスク関連ドキュメントの翻訳が完了しました。"}
