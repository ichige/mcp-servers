Resourceは、MCP Clientが読み取ることができるデータやファイルを表します。Resource Templateはこの概念を拡張し、URIに渡されたパラメータに基づいて動的に生成されるResourceをClientがリクエストできるようにします。

FastMCPは、主に `@mcp.resource` Decoratorを使用して、静的および動的なResourceの定義を簡素化します。

## What Are Resources?

Resourceは、LLMまたはClientアプリケーションにデータへの読み取り専用アクセスを提供します。ClientがResourceのURIをリクエストすると：

1.  FastMCPは対応するResource定義を見つけます。
2.  動的（関数によって定義されている）な場合、その関数が実行されます。
3.  コンテンツ（テキスト、JSON、バイナリデータ）がClientに返されます。

これにより、LLMはファイル、データベースのコンテンツ、設定、または会話に関連する動的に生成された情報にアクセスできるようになります。

## Resources

### The `@resource` Decorator

Resourceを定義する最も一般的な方法は、Python関数を修飾（decorate）することです。Decoratorには、Resourceの一意のURIが必要です。

```python
import json
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

# 文字列を返す基本的な動的Resource
@mcp.resource("resource://greeting")
def get_greeting() -> str:
    """シンプルな挨拶メッセージを提供します。"""
    return "Hello from FastMCP Resources!"

# JSONデータを返すResource
@mcp.resource("data://config")
def get_config() -> str:
    """アプリケーションの設定をJSONとして提供します。"""
    return json.dumps({
        "theme": "dark",
        "version": "1.2.0",
        "features": ["tools", "resources"],
    })
```

**Key Concepts:**

*   **URI:** `@resource` の最初のArgumentは、Clientがこのデータをリクエストするために使用する一意のURI（例: `"resource://greeting"`）です。
*   **Lazy Loading:** 修飾された関数（`get_greeting`、`get_config`）は、Clientが `resources/read` を介してそのResource URIを明確にリクエストしたときにのみ実行されます。
*   **Inferred Metadata:** デフォルトでは：
    *   Resource名: 関数名（`get_greeting`）から取得されます。
    *   Resourceの説明: 関数のdocstringから取得されます。

#### Decorator Arguments

`@mcp.resource` DecoratorのArgumentを使用して、Resourceのプロパティをカスタマイズできます：

```python
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

# メタデータを指定する例
@mcp.resource(
    uri="data://app-status",      # 明示的なURI（必須）
    name="ApplicationStatus",     # カスタム名
    description="Provides the current status of the application.", # カスタムの説明
    mime_type="application/json", # 明示的なMIMEタイプ
    tags={"monitoring", "status"}, # 分類用のタグ
    meta={"version": "2.1", "team": "infrastructure"}  # カスタムメタデータ
)
def get_application_status() -> str:
    """内部関数の説明（上記でdescriptionが提供されている場合は無視されます）。"""
    return json.dumps({"status": "ok", "uptime": 12345, "version": mcp.settings.version})
```

#### Using with Methods

インスタンスメソッドまたはクラスメソッドを修飾する場合は、スタンドアロンの `@resource` Decoratorを使用し、バインドされたメソッドを登録します。パターンの詳細については、[Tools: Using with Methods](/servers/tools#using-with-methods)を参照してください。

### Return Values

Resource関数は、以下の3つのReturn typeのいずれかを返す必要があります：

-   **`str`**: `TextResourceContents` として送信されます（デフォルトで `mime_type="text/plain"`）。
-   **`bytes`**: Base64エンコードされ、`BlobResourceContents` として送信されます。適切な `mime_type`（例: `"image/png"`、`"application/octet-stream"`）を指定する必要があります。
-   **`ResourceResult`**: コンテンツ、MIMEタイプ、およびメタデータを完全に制御します。以下の [ResourceResult](#resourceresult) を参照してください。

<Note>
辞書やリストなどの構造化データを返すには、`json.dumps()` を使用してJSON文字列にシリアライズします。この明示的なアプローチにより、ClientがResourceを読み取る実行時ではなく、開発中に型チェッカーがエラーを捕捉できるようになります。
</Note>

#### ResourceResult

<VersionBadge version="3.0.0" />

`ResourceResult` を使用すると、複数のコンテンツアイテム、アイテムごとのMIMEタイプ、およびアイテムレベルと結果レベルの両方のメタデータなど、Resourceのレスポンスを明示的に制御できます。

```python
from fastmcp import FastMCP
from fastmcp.resources import ResourceResult, ResourceContent

mcp = FastMCP()

@mcp.resource("data://users")
def get_users() -> ResourceResult:
    return ResourceResult(
        contents=[
            ResourceContent(content='[{"id": 1}]', mime_type="application/json"),
            ResourceContent(content="# Users\n...", mime_type="text/markdown"),
        ],
        meta={"total": 1}
    )
```

`ResourceContent` は3つのフィールドを受け入れます：

**`content`** - 実際のResourceコンテンツ。`str`（テキストコンテンツ）または `bytes`（バイナリコンテンツ）を指定できます。これがClientに返されるデータです。

**`mime_type`** - コンテンツのオプションのMIMEタイプ。文字列コンテンツの場合は `"text/plain"`、バイナリコンテンツの場合は `"application/octet-stream"` がデフォルトです。

**`meta`** - MCPレスポンスの `meta` フィールドに含まれるオプションのメタデータ辞書。コンテンツセキュリティポリシー（CSP）ヘッダー、キャッシュのヒント、またはその他のClient固有のデータなどの実行時メタデータにこれを使用します。

単純なケースでは、`str` または `bytes` を直接 `ResourceResult` に渡すことができます：

```python
return ResourceResult("plain text")           # ResourceContentに自動変換されます
return ResourceResult(b"\x00\x01\x02")         # バイナリコンテンツ
```

### Component Visibility

<VersionBadge version="3.0.0" />

Serverレベルの有効化制御を使用して、Clientに対して有効にするResourceを制御できます。無効化されたResourceは `list_resources` に表示されず、読み取ることもできません。

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.resource("data://public", tags={"public"})
def get_public(): return "public"

@mcp.resource("data://secret", tags={"internal"})
def get_secret(): return "secret"

# キーによって特定のResourceを無効化する
mcp.disable(keys={"resource:data://secret"})

# タグによってResourceを無効化する
mcp.disable(tags={"internal"})

# または許可リストモードを使用する - 特定のタグを持つResourceのみを有効化する
mcp.enable(tags={"public"}, only=True)
```

キーの形式、タグベースのフィルタリング、プロバイダーレベルの制御を含む、完全な可視性制御APIについては、[Visibility](/servers/visibility)を参照してください。


### Accessing MCP Context

<VersionBadge version="2.2.5" />

ResourceおよびResource Templateは、`Context` オブジェクトを通じて追加のMCP情報および機能にアクセスできます。これにアクセスするには、型アノテーション `Context` を持つArgumentをResource関数に追加します：

```python {6, 14}
from fastmcp import FastMCP, Context

mcp = FastMCP(name="DataServer")

@mcp.resource("resource://system-status")
async def get_system_status(ctx: Context) -> str:
    """システムステータス情報を提供します。"""
    return json.dumps({
        "status": "operational",
        "request_id": ctx.request_id
    })

@mcp.resource("resource://{name}/details")
async def get_details(name: str, ctx: Context) -> str:
    """特定の名前の詳細を取得します。"""
    return json.dumps({
        "name": name,
        "accessed_at": ctx.request_id
    })
```

Contextオブジェクトとそのすべての機能の完全なドキュメントについては、[Context documentation](/servers/context)を参照してください。


### Async Resources

FastMCPは、`async def` と通常の `def` の両方のResource関数をサポートしています。同期関数は、イベントループのブロックを避けるために自動的にスレッドプールで実行されます。

I/Oバウンドな操作の場合、非同期関数の方が効率的です：

```python
import aiofiles
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

@mcp.resource("file:///app/data/important_log.txt", mime_type="text/plain")
async def read_important_log() -> str:
    """特定のログファイルから非同期にコンテンツを読み取ります。"""
    try:
        async with aiofiles.open("/app/data/important_log.txt", mode="r") as f:
            content = await f.read()
        return content
    except FileNotFoundError:
        return "Log file not found."
```


### Resource Classes

`@mcp.resource` は動的コンテンツに最適ですが、`mcp.add_resource()` と具体的な `Resource` サブクラスを使用して、事前定義されたResource（静的ファイルや単純なテキストなど）を直接登録することもできます。

```python
from pathlib import Path
from fastmcp import FastMCP
from fastmcp.resources import FileResource, TextResource, DirectoryResource

mcp = FastMCP(name="DataServer")

# 1. 静的ファイルを直接公開する
readme_path = Path("./README.md").resolve()
if readme_path.exists():
    # file:// URIスキームを使用する
    readme_resource = FileResource(
        uri=f"file://{readme_path.as_posix()}",
        path=readme_path, # 実際のファイルへのパス
        name="README File",
        description="プロジェクトのREADME。",
        mime_type="text/markdown",
        tags={"documentation"}
    )
    mcp.add_resource(readme_resource)

# 2. シンプルな事前定義されたテキストを公開する
notice_resource = TextResource(
    uri="resource://notice",
    name="Important Notice",
    text="System maintenance scheduled for Sunday.",
    tags={"notification"}
)
mcp.add_resource(notice_resource)

# 3. ディレクトリのリストを公開する
data_dir_path = Path("./app_data").resolve()
if data_dir_path.is_dir():
    data_listing_resource = DirectoryResource(
        uri="resource://data-files",
        path=data_dir_path, # ディレクトリへのパス
        name="Data Directory Listing",
        description="データディレクトリで利用可能なファイルをリストします。",
        recursive=False # サブディレクトリをリストするにはTrueに設定します
    )
    mcp.add_resource(data_listing_resource) # ファイルのJSONリストを返します
```

**Common Resource Classes:**

-   `TextResource`: 単純な文字列コンテンツ用。
-   `BinaryResource`: 生の `bytes` コンテンツ用。
-   `FileResource`: ローカルファイルパスからコンテンツを読み取ります。テキスト/バイナリモード、エンコーディング、および遅延読み込み（lazy reading）を処理します。
-   `HttpResource`: HTTP(S) URLからコンテンツを取得します（`httpx` が必要です）。
-   `DirectoryResource`: ローカルディレクトリ内のファイルをリストします（JSONを返します）。
-   (`FunctionResource`: `@mcp.resource` によって使用される内部クラス)。

コンテンツが静的である場合、またはファイル/URLから直接取得される場合は、専用のPython関数を必要としないため、これらを使用してください。

### Notifications

<VersionBadge version="2.9.1" />

FastMCPは、ResourceまたはTemplateが追加、有効化、または無効化されたときに、接続されているClientに `notifications/resources/list_changed` 通知を自動的に送信します。これにより、Clientは変更を手動でポーリングすることなく、現在のResourceセットを最新の状態に保つことができます。

```python
@mcp.resource("data://example")
def example_resource() -> str:
    return "Hello!"

# これらの操作は通知をトリガーします：
mcp.add_resource(example_resource)                   # resources/list_changed 通知を送信します
mcp.disable(keys={"resource:data://example"})        # resources/list_changed 通知を送信します
mcp.enable(keys={"resource:data://example"})         # resources/list_changed 通知を送信します
```

通知は、これらの操作がアクティブなMCPリクエストコンテキスト内（例: Toolやその他のMCP操作内から呼び出された場合）で発生した場合にのみ送信されます。Serverの初期化中に実行された操作は、通知をトリガーしません。

Clientは、[message handler](/clients/notifications)を使用してこれらの通知を処理し、Resourceリストを自動的に更新したり、インターフェースを更新したりできます。

### Annotations

<VersionBadge version="2.11.0" />

FastMCPでは、アノテーションを通じてResourceに特化したメタデータを追加できます。これらのアノテーションは、LLMのPromptでトークンコンテキストを消費することなく、Resourceがどのように動作するかをClientアプリケーションに伝達します。

アノテーションは、Clientアプリケーションにおいて以下のようないくつかの目的を果たします：
- Resourceが読み取り専用であるか、副作用がある可能性があるかを示す
- Resourceの安全性プロファイル（冪等か非冪等か）を説明する
- Clientがキャッシュとアクセスパターンを最適化するのを支援する

`@mcp.resource` Decoratorの `annotations` Parameterを使用して、Resourceにアノテーションを追加できます：

```python
@mcp.resource(
    "data://config",
    annotations={
        "readOnlyHint": True,
        "idempotentHint": True
    }
)
def get_config() -> str:
    """アプリケーションの設定を取得します。"""
    return json.dumps({"version": "1.0", "debug": False})
```

FastMCPは以下の標準アノテーションをサポートしています：

| Annotation | Type | Default | Purpose |
| :--------- | :--- | :------ | :------ |
| `readOnlyHint` | boolean | true | Resourceが副作用なしにデータのみを提供するかどうかを示します |
| `idempotentHint` | boolean | true | 繰り返しの読み取りが1回の読み取りと同じ効果を持つかどうかを示します |

アノテーションはより良いユーザーエクスペリエンスの構築に役立ちますが、あくまでアドバイザリーなヒントとして扱うべきであることに注意してください。これらはClientアプリケーションが適切なUI要素を提示し、アクセスパターンを最適化するのに役立ちますが、それ自体で動作を強制するものではありません。常に、Resourceが実際に何を行うかをアノテーションが正確に表すようにすることに焦点を当ててください。

## Resource Templates

Resource Templateを使用すると、ClientはURIに埋め込まれたパラメータに依存するコンテンツを持つResourceをリクエストできます。**同じ `@mcp.resource` Decorator** を使用してTemplateを定義しますが、URI文字列に `{parameter_name}` プレースホルダーを含め、関数シグネチャに対応するArgumentを追加します。

Resource Templateは、通常のResourceとほとんどの設定オプション（name、description、mime_type、tags、annotations）を共有しますが、関数のArgumentにマッピングされるURIパラメータを定義する機能が追加されています。

Resource Templateは、パラメータの一意のセットごとに新しいResourceを生成します。つまり、Resourceをオンデマンドで動的に作成できます。たとえば、Resource Template `"user://profile/{name}"` が登録されている場合、MCP Clientは `"user://profile/ford"` または `"user://profile/marvin"` をリクエストして、各Resourceを個別に登録することなく、これら2つのユーザープロファイルのいずれかをResourceとして取得できます。

<Tip>
`*args` を持つ関数は、Resource Templateとしてサポートされていません。ただし、ToolやPromptとは異なり、Resource Templateは `**kwargs` をサポートしています。これは、URI Templateが特定のパラメータ名を定義し、それらが収集されてキーワードArgumentとして渡されるためです。
</Tip>

以下は、2つのResource Templateを定義する方法を示す完全な例です：

```python
import json
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

# Template URIに {city} プレースホルダーを含める
@mcp.resource("weather://{city}/current")
def get_weather(city: str) -> str:
    """特定の都市の天気情報を提供します。"""
    return json.dumps({
        "city": city.capitalize(),
        "temperature": 22,
        "condition": "Sunny",
        "unit": "celsius"
    })

# 複数のパラメータとアノテーションを持つTemplate
@mcp.resource(
    "repos://{owner}/{repo}/info",
    annotations={
        "readOnlyHint": True,
        "idempotentHint": True
    }
)
def get_repo_info(owner: str, repo: str) -> str:
    """GitHubリポジトリに関する情報を取得します。"""
    return json.dumps({
        "owner": owner,
        "name": repo,
        "full_name": f"{owner}/{repo}",
        "stars": 120,
        "forks": 48
    })
```

これら2つのTemplateが定義されると、ClientはさまざまなResourceをリクエストできます：
- `weather://london/current` → ロンドンの天気を返します
- `weather://paris/current` → パリの天気を返します
- `repos://PrefectHQ/fastmcp/info` → PrefectHQ/fastmcpリポジトリに関する情報を返します
- `repos://prefecthq/prefect/info` → prefecthq/prefectリポジトリに関する情報を返します

### RFC 6570 URI Templates


FastMCPは、Resource Templateに [RFC 6570 URI Templates](https://datatracker.ietf.org/doc/html/rfc6570) を実装しており、パラメータ化されたURIを定義するための標準化された方法を提供します。これには、単純な展開、ワイルドカードパスパラメータ、およびフォームスタイルのクエリパラメータのサポートが含まれます。

#### Wildcard Parameters

<VersionBadge version="2.2.4" />

Resource Templateは、複数のパスセグメントに一致するワイルドカードパラメータをサポートしています。標準のパラメータ（`{param}`）は単一のパスセグメントにのみ一致し、"/" の境界を越えませんが、ワイルドカードパラメータ（`{param*}`）はスラッシュを含む複数のセグメントをキャプチャできます。ワイルドカードは、URI Template的定義された部分（リテラルまたは別のパラメータ）の*直前まで*のすべての後続のパスセグメントをキャプチャします。これにより、単一のURI Templateに複数のワイルドカードパラメータを含めることができます。

```python {15, 23}
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")


# 標準のパラメータは1つのセグメントにのみ一致します
@mcp.resource("files://{filename}")
def get_file(filename: str) -> str:
    """名前でファイルを取得します。"""
    # files://<単一セグメント> にのみ一致します
    return f"File content for: {filename}"


# ワイルドカードパラメータは複数のセグメントに一致できます
@mcp.resource("path://{filepath*}")
def get_path_content(filepath: str) -> str:
    """特定のパスのコンテンツを取得します。"""
    # path://docs/server/resources.mdx に一致できます
    return f"Content at path: {filepath}"


# 標準パラメータとワイルドカードパラメータの混在
@mcp.resource("repo://{owner}/{path*}/template.py")
def get_template_file(owner: str, path: str) -> dict:
    """特定のリポジトリとパスからファイルを取得しますが、Resourceが `template.py` で終わる場合のみです"""
    # repo://PrefectHQ/fastmcp/src/resources/template.py に一致できます
    return {
        "owner": owner,
        "path": path + "/template.py",
        "content": f"File at {path}/template.py in {owner}'s repository"
    }
```

ワイルドカードパラメータは以下の場合に役立ちます：

- ファイルパスや階層データを扱う場合
- 可変長のパスセグメントをキャプチャする必要があるAPIを作成する場合
- REST APIに似たURLライクなパターンを構築する場合

通常のパラメータと同様に、各ワイルドカードパラメータは関数シグネチャのNamed Argumentである必要があり、すべての必須の関数ArgumentはURI Templateに含まれる必要があることに注意してください。

#### Query Parameters

<VersionBadge version="2.13.0" />

FastMCPは、`{?param1,param2}` 構文を使用したRFC 6570フォームスタイルのクエリパラメータをサポートしています。クエリパラメータは、パスを煩雑にすることなく、オプションの設定をResourceに渡すためのクリーンな方法を提供します。

クエリパラメータはオプション的関数Argument（デフォルト値を持つ）である必要がありますが、パスパラメータは必須の関数Argumentにマッピングされます。これにより、明確な分離が強制されます：必須データはパスに、オプションの設定はクエリパラメータに配置されます。

```python
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

# 基本的なクエリパラメータ
@mcp.resource("data://{id}{?format}")
def get_data(id: str, format: str = "json") -> str:
    """指定された形式でデータを取得します。"""
    if format == "xml":
        return f"<data id='{id}' />"
    return f'{"id": "{id}"}'

# 型強制を伴う複数のクエリパラメータ
@mcp.resource("api://{endpoint}{?version,limit,offset}")
def call_api(endpoint: str, version: int = 1, limit: int = 10, offset: int = 0) -> dict:
    """ページネーション付きでAPIエンドポイントを呼び出します。"""
    return {
        "endpoint": endpoint,
        "version": version,
        "limit": limit,
        "offset": offset,
        "results": fetch_results(endpoint, version, limit, offset)
    }

# ワイルドカードを伴うクエリパラメータ
@mcp.resource("files://{path*}{?encoding,lines}")
def read_file(path: str, encoding: str = "utf-8", lines: int = 100) -> str:
    """オプションのエンコーディングと行数制限付きでファイルを読み取ります。"""
    return read_file_content(path, encoding, lines)
```

**Example requests:**
- `data://123` → デフォルトの形式 `"json"` を使用します
- `data://123?format=xml` → 形式 `"xml"` を使用します
- `api://users?version=2&limit=50` → `version=2, limit=50, offset=0`
- `files://src/main.py?encoding=ascii&lines=50` → カスタムエンコーディングと行数制限

FastMCPは、関数の型ヒント（`int`、`float`、`bool`、`str`）に基づいて、クエリパラメータの文字列値を正しい型に自動的に強制（coerce）します。

**Query parameters vs. hidden defaults:**

クエリパラメータは、オプションの設定をClientに公開します。オプションのパラメータをClientから完全に隠す（常にデフォルトを使用する）には、単にURI Templateからそれらを省略します：

```python
# Clientはクエリ文字列を介して max_results をオーバーライドできます
@mcp.resource("search://{query}{?max_results}")
def search_configurable(query: str, max_results: int = 10) -> dict:
    return {"query": query, "limit": max_results}

# Clientは max_results をオーバーライドできません（URI Templateにありません）
@mcp.resource("search://{query}")
def search_fixed(query: str, max_results: int = 10) -> dict:
    return {"query": query, "limit": max_results}
```

### Template Parameter Rules

<VersionBadge version="2.2.0" />

FastMCPは、Resource Templateを作成する際に以下の検証ルールを強制します：

1. **必須の関数Argument**（デフォルト値なし）は、URIパスのTemplateに含まれる必要があります
2. **クエリパラメータ**（`{?param}` 構文で指定）は、デフォルト値を持つオプションの関数Argumentである必要があります
3. **すべてのURI Templateパラメータ**（パスおよびクエリ）は、関数Argumentとして存在する必要があります

オプションの関数Argument（デフォルト値を持つもの）は以下のようになります：
- クエリパラメータ（`{?param}`）として含める - Clientはクエリ文字列を介してオーバーライドできます
- URI Templateから省略する - 常にデフォルト値を使用し、Clientには公開されません
- 代替のパスTemplateで使用する - 同じResourceにアクセスするための複数の方法を可能にします

**Multiple templates for one function:**

Decoratorを手動で適用することにより、異なるURIパターンを通じて同じ関数を公開する複数のResource Templateを作成します：

```python
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

# 異なる識別子でアクセスできるユーザー検索関数を定義する
def lookup_user(name: str | None = None, email: str | None = None) -> dict:
    """名前またはメールアドレスでユーザーを検索します。"""
    if email:
        return find_user_by_email(email)  # pseudocode
    elif name:
        return find_user_by_name(name)  # pseudocode
    else:
        return {"error": "No lookup parameters provided"}

# 同じ関数に複数のDecoratorを手動で適用する
mcp.resource("users://email/{email}")(lookup_user)
mcp.resource("users://name/{name}")(lookup_user)
```

これで、LLMまたはClientは2つの異なる方法でユーザー情報を取得できます：
- `users://email/alice@example.com` → メールアドレスでユーザーを検索します（name=None）
- `users://name/Bob` → 名前でユーザーを検索します（email=None）

このアプローチにより、実装をクリーンでシンプルに保ちながら、単一の関数を複数のURIパターンで登録できます。

Templateは、RESTライクな原則に従ってパラメータ化されたデータアクセスポイントを公開するための強力な方法を提供します。

## Error Handling

<VersionBadge version="2.4.1" />

Resource関数でエラーが発生した場合、標準のPython例外（`ValueError`、`TypeError`、`FileNotFoundError`、カスタム例外など）またはFastMCPの `ResourceError` を発生させることができます。

デフォルトでは、すべての例外（その詳細を含む）がログに記録され、ClientのLLMに送り返されるMCPエラーレスポンスに変換されます。これにより、LLMは失敗を理解し、適切に反応することができます。

セキュリティ上の理由から内部エラーの詳細をマスクしたい場合は、以下の方法があります：

1. `FastMCP` インスタンスを作成する際に `mask_error_details=True` パラメータを使用する：
```python
mcp = FastMCP(name="SecureServer", mask_error_details=True)
```

2. または、`ResourceError` を使用して、Clientに送信されるエラー情報を明示的に制御する：
```python
from fastmcp import FastMCP
from fastmcp.exceptions import ResourceError

mcp = FastMCP(name="DataServer")

@mcp.resource("resource://safe-error")
def fail_with_details() -> str:
    """このResourceは詳細なエラー情報を提供します。"""
    # ResourceErrorのコンテンツは、mask_error_detailsの設定に関係なく、
    # 常にClientに送り返されます
    raise ResourceError("Unable to retrieve data: file not found")

@mcp.resource("resource://masked-error")
def fail_with_masked_details() -> str:
    """このResourceは、mask_error_details=Trueの場合に内部エラーの詳細をマスクします。"""
    # このメッセージは、mask_error_details=Trueの場合にマスクされます
    raise ValueError("Sensitive internal file path: /etc/secrets.conf")

@mcp.resource("data://{id}")
def get_data_by_id(id: str) -> dict:
    """Template Resourceも同じエラー処理パターンをサポートしています。"""
    if id == "secure":
        raise ValueError("Cannot access secure data")
    elif id == "missing":
        raise ResourceError("Data ID 'missing' not found in database")
    return {"id": id, "value": "data"}
```

`mask_error_details=True` の場合、`ResourceError` からのエラーメッセージのみに詳細が含まれ、他の例外は一般的なメッセージに変換されます。

## Server Behavior

### Duplicate Resources

<VersionBadge version="2.1.0" />

FastMCP Serverが、同じURIを持つ複数のResourceまたはTemplateを登録しようとする試みをどのように処理するかを設定できます。`FastMCP` の初期化時に `on_duplicate_resources` 設定を使用します。

```python
from fastmcp import FastMCP

mcp = FastMCP(
    name="ResourceServer",
    on_duplicate_resources="error" # 重複時にエラーを発生させる
)

@mcp.resource("data://config")
def get_config_v1(): return {"version": 1}

# "data://config" はすでに登録されており、動作が "error" であるため、
# この登録の試みはValueErrorを発生させます。
# @mcp.resource("data://config")
# def get_config_v2(): return {"version": 2}
```

重複時の動作オプションは以下の通りです：

-   `"warn"`（デフォルト）: 警告をログに記録し、新しいResource/Templateが古いものを置き換えます。
-   `"error"`: `ValueError` を発生させ、重複登録を防ぎます。
-   `"replace"`: 既存のResource/Templateを新しいもので静かに置き換えます。
-   `"ignore"`: 元のResource/Templateを保持し、新しい登録の試みを無視します。
