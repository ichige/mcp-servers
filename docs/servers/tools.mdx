Toolは、LLMが外部システムと対話し、コードを実行し、トレーニングデータにないデータにアクセスできるようにするためのコアな構成要素です。FastMCPでは、ToolはMCPプロトコルを通じてLLMに公開されるPython関数です。

FastMCPのToolは、通常のPython関数を、会話中にLLMが呼び出すことができる機能に変換します。LLMがToolを使用することを決定すると、以下の処理が行われます：

1.  Toolのスキーマに基づいたパラメータを含むリクエストを送信します。
2.  FastMCPは、関数のシグネチャに対してこれらのパラメータを検証します。
3.  検証された入力を使用して関数が実行されます。
4.  結果がLLMに返され、LLMはそれを応答で使用できます。

これにより、LLMはデータベースのクエリ、APIの呼び出し、計算の実行、ファイルへのアクセスなどのタスクを実行できるようになり、トレーニングデータに含まれる以上の機能に拡張されます。


## The `@tool` Decorator

Toolの作成は、Python関数を `@mcp.tool` でデコレートするだけで非常に簡単です：

```python
from fastmcp import FastMCP

mcp = FastMCP(name="CalculatorServer")

@mcp.tool
def add(a: int, b: int) -> int:
    """2つの整数を足し合わせます。"""
    return a + b
```

このToolが登録されると、FastMCPは自動的に以下の処理を行います：
- 関数名（`add`）をTool名として使用します。
- 関数のdocstring（`2つの整数を足し合わせます...`）をToolの説明として使用します。
- 関数のパラメータと型アノテーションに基づいて入力スキーマを生成します。
- パラメータの検証とエラー報告を処理します。

Python関数の定義方法によって、LLM Clientに対するToolの表示と動作が決まります。

<Tip>
`*args` または `**kwargs` を持つ関数は、Toolとしてサポートされていません。この制限は、FastMCPがMCPプロトコル用の完全なパラメータスキーマを生成する必要があり、可変長引数リストではそれが不可能であるために存在します。
</Tip>

### Decorator Arguments

FastMCPは関数から名前と説明を推論しますが、`@mcp.tool` DecoratorのArgumentを使用してこれらを上書きし、追加のメタデータを追加することができます：

```python
@mcp.tool(
    name="find_products",           # LLM向けのカスタムTool名
    description="オプションのカテゴリフィルタリングを使用して製品カタログを検索します。", # カスタムの説明
    tags={"catalog", "search"},      # 整理/フィルタリング用のオプションのタグ
    meta={"version": "1.2", "author": "product-team"}  # カスタムメタデータ
)
def search_products_implementation(query: str, category: str | None = None) -> list[dict]:
    """内部関数の説明（上記で説明が提供されている場合は無視されます）。"""
    # 実装...
    print(f"カテゴリ '{category}' で '{query}' を検索しています")
    return [{"id": 2, "name": "Another Product"}]
```

### Using with Methods

`@mcp.tool` DecoratorはToolを即座に登録しますが、これはインスタンスメソッドやクラスメソッドでは機能しません（必須パラメータとして `self` や `cls` が表示されてしまいます）。メソッドの場合は、スタンドアロンの `@tool` Decoratorを使用してメ タデータを添付し、その後バインドされたメソッドを登録します：

```python
from fastmcp import FastMCP
from fastmcp.tools import tool

class Calculator:
    def __init__(self, multiplier: int):
        self.multiplier = multiplier

    @tool()
    def multiply(self, x: int) -> int:
        """xにインスタンスの乗数を掛けます。"""
        return x * self.multiplier

calc = Calculator(multiplier=3)
mcp = FastMCP()
mcp.add_tool(calc.multiply)  # 正しいスキーマで登録されます（'self' ではなく 'x' のみ）
```

### Async Support

FastMCPは、非同期（`async def`）関数と同期（`def`）関数の両方をToolとしてサポートしています。同期Toolはイベントループのブロックを避けるために自動的にスレッドプールで実行されるため、個々のToolがブロッキング操作を実行しても、複数のTool呼び出しを並行して実行できます。

```python
from fastmcp import FastMCP
import time

mcp = FastMCP()

@mcp.tool
def slow_tool(x: int) -> int:
    """この同期関数は、他の並行リクエストをブロックしません。"""
    time.sleep(2)  # イベントループ上ではなく、スレッドプールで実行されます
    return x * 2
```

ネットワークリクエストやデータベースクエリなどのI/Oバウンドな操作の場合、スレッドプールのディスパッチよりも効率的であるため、依然として非同期Toolが推奨されます。同期ライブラリを使用する場合や、スレッドのオーバーヘッドが問題にならない単純な操作の場合は、同期Toolを使用してください。

## Arguments

デフォルトでは、FastMCPは関数のシグネチャと型アノテーションを検査することで、Python関数をMCP Toolに変換します。これにより、ToolのArgumentに標準のPython型アノテーションを使用できます。一般的に、フレームワークは「ただ動く」ことを目指しています。パラメータのデフォルト値や型アノテーションなどの慣用的なPythonの動作は、自動的にMCPスキーマに変換されます。ただし、Toolの動作をカスタマイズする方法はいくつかあります。

<Note>
FastMCPは、JSON Schemaの参照を完全にサポートしていないMCP Client（例: VS Code Copilot、Claude Desktop）との互換性を確保するために、Toolスキーマ内の `$ref` エントリを自動的に逆参照（dereference）します。これは、共有型を持つ複雑なPydantic モデルが、`$defs` 参照を使用するのではなく、スキーマ内にインライン化されることを意味します。

逆参照はミドルウェアを介して提供時に行われるため、スキーマは `$ref` がそのままの状態で保存され、Clientに送信されるときにのみインライン化されます。Clientが `$ref` を正しく処理できることがわかっており、より小さなスキーマを好む場合は、オプ トアウトできます：

```python
mcp = FastMCP("my-server", dereference_schemas=False)
```
</Note>

### Type Annotations

MCP Toolには型付きのArgumentがあり、FastMCPは型アノテーションを使用してそれらの型を決定します。したがって、ToolのArgumentには標準のPython型アノテーションを使用する必要があります：

```python
@mcp.tool
def analyze_text(
    text: str,
    max_tokens: int = 100,
    language: str | None = None
) -> dict:
    """提供されたテキストを分析します。"""
    # 実装...
```

FastMCPは、すべてのPydantic型を含む、幅広い型アノテーションをサポートしています：

| Type Annotation         | Example                       | Description                         |
| :---------------------- | :---------------------------- | :---------------------------------- |
| 基本型             | `int`, `float`, `str`, `bool` | 単純なスカラー値 |
| バイナリデータ             | `bytes`                       | バイナリコンテンツ（自動デコードされたbase64ではなく、生の文字列） |
| 日付と時刻           | `datetime`, `date`, `timedelta` | 日付と時刻のオブジェクト（ISOフォーマットの文字列） |
| コレクション型        | `list[str]`, `dict[str, int]`, `set[int]` | アイテムのコレクション |
| オプショナル型          | `float \| None`, `Optional[float]`| null/省略される可能性のあるパラメータ |
| ユニオン型             | `str \| int`, `Union[str, int]`| 複数の型を受け入れるパラメータ |
| 制約付き型       | `Literal["A", "B"]`, `Enum`   | 特定の許可された値を持つパラメータ |
| パス                   | `Path`                        | ファイルシステムパス（文字列から自動変換） |
| UUID                   | `UUID`                        | 汎用一意識別子（文字列から自動変換） |
| Pydanticモデル         | `UserData`                    | 検証を伴う複雑な構造化データ |

FastMCPは、すべてのPydanticカスタム型を含む、Pydanticがフィールドとしてサポートするすべての型をサポートしています。注意すべきFastMCP固有の動作がいくつかあります：

**バイナリデータ**: `bytes` パラメータは、自動的なbase64デコードなしで生の文字列を受け入れます。base64データの場合は、`str` を使用し、`base64.b64decode()` で手動でデコードしてください。

**Enum**: Clientは名前（`"RED"`）ではなく、Enumの値（`"red"`）を送信します。関数はEnumメンバー（`Color.RED`）を受け取ります。

**パスとUUID**: 文字列入力は自動的に `Path` および `UUID` オブジェクトに変換されます。

**Pydanticモデル**: 文字列化されたJSONではなく、JSONオブジェクト（辞書）として提供する必要があります。柔軟な検証を使用しても、`{"user": {"name": "Alice"}}` は機能しますが、`{"user": '{"name": "Alice"}'}` は機能しません。

### Optional Arguments

FastMCPは、Pythonの標準的な関数パラメータの規則に従います。デフォルト値のないパラメータは必須であり、デフォルト値のあるパラメータはオプションです。

```python
@mcp.tool
def search_products(
    query: str,                   # 必須 - デフォルト値なし
    max_results: int = 10,        # オプション - デフォルト値あり
    sort_by: str = "relevance",   # オプション - デフォルト値あり
    category: str | None = None   # オプション - Noneにできる
) -> list[dict]:
    """製品カタログを検索します。"""
    # 実装...
```

この例では、LLMは `query` パラメータを提供する必要がありますが、`max_results`、`sort_by`、および `category` は明示的に提供されない場合、それぞれのデフォルト値を使用します。

### Validation Modes

<VersionBadge version="2.13.0" />

デフォルトでは、FastMCPはPydanticの柔軟な検証を使用し、互換性のある入力を型アノテーションに一致するように強制変換（coerce）します。これにより、値の文字列表現（整数パラメータに対する `"10"` など）を送信する可能性のあるLLM Clientとの互換性が向上します。

型の不一致を拒否するより厳密な検証が必要な場合は、厳密な入力検証（strict input validation）を有効にすることができます。厳密モードでは、MCP SDKの組み込みJSON Schema検証を使用して、関数に渡す前に正確なスキーマに対して入力を検証します：

```python
# このServerの厳密な検証を有効にする
mcp = FastMCP("StrictServer", strict_input_validation=True)

@mcp.tool
def add_numbers(a: int, b: int) -> int:
    """2つの数値を足し合わせます。"""
    return a + b

# strict_input_validation=True の場合、{"a": "10", "b": "20"} を送信すると失敗します
# strict_input_validation=False (デフォルト) の場合、整数に強制変換されます
```

**検証動作の比較:**

| 入力タイプ | strict_input_validation=False (デフォルト) | strict_input_validation=True |
| :--------- | :-------------------------------------- | :--------------------------- |
| 文字列の整数（`int` に対する `"10"`） | ✅ 整数に強制変換 | ❌ 検証エラー |
| 文字列の浮動小数点数（`float` に対する `"3.14"`） | ✅ 浮動小数点数に強制変換 | ❌ 検証エラー |
| 文字列のブール値（`bool` に対する `"true"`） | ✅ ブール値に強制変換 | ❌ 検証エラー |
| 文字列要素を持つリスト（`list[int]` に対する `["1", "2"]`） | ✅ 要素が強制変換される | ❌ 検証エラー |
| 型の不一致があるPydanticモデルのフィールド | ✅ フィールドが強制変換される | ❌ 検証エラー |
| 無効な値（`int` に対する `"abc"`） | ❌ 検証エラー | ❌ 検証エラー |

<Note>
**Pydanticモデルに関する注意:** `strict_input_validation=False` の場合でも、Pydanticモデルのパラメータは、文字列化されたJSONではなく、JSONオブジェクト（辞書）として提供される必要があります。たとえば、`{"user": {"name": "Alice"}}` は機能 しますが、`{"user": '{"name": "Alice"}'}` は機能しません。
</Note>

デフォルトの柔軟な検証モードは、Pydanticの検証を通じて強力な型安全性を提供しつつ、一般的なLLM Clientの動作を適切に処理するため、ほとんどのユースケースで推奨されます。

### Parameter Metadata

パラメータに関する追加のメタデータは、いくつかの方法で提供できます：

#### Simple String Descriptions

<VersionBadge version="2.11.0" />

基本的なパラメータの説明には、`Annotated` を使用した便利な省略記法を使用できます：

```python
from typing import Annotated

@mcp.tool
def process_image(
    image_url: Annotated[str, "処理する画像のURL"],
    resize: Annotated[bool, "画像をリサイズするかどうか"] = False,
    width: Annotated[int, "ピクセル単位のターゲット幅"] = 800,
    format: Annotated[str, "出力画像フォーマット"] = "jpeg"
) -> dict:
    """オプションのリサイズを使用して画像を処理します。"""
    # 実装...
```

この省略構文は `Field(description=...)` を使用するのと同じですが、単純な説明の場合はより簡潔です。

<Tip>
この省略構文は、単一の文字列の説明を持つ `Annotated` 型にのみ適用されます。
</Tip>

#### Advanced Metadata with Field

検証の制約や高度なメタデータについては、`Annotated` と共にPydanticの `Field` クラスを使用します：

```python
from typing import Annotated
from pydantic import Field

@mcp.tool
def process_image(
    image_url: Annotated[str, Field(description="処理する画像のURL")],
    resize: Annotated[bool, Field(description="画像をリサイズするかどうか")] = False,
    width: Annotated[int, Field(description="ピクセル単位のターゲット幅", ge=1, le=2000)] = 800,
    format: Annotated[
        Literal["jpeg", "png", "webp"],
        Field(description="出力画像フォーマット")
    ] = "jpeg"
) -> dict:
    """オプションのリサイズを使用して画像を処理します。"""
    # 実装...
```


Fieldをデフォルト値として使用することもできますが、Annotatedアプローチが推奨されます：

```python
@mcp.tool
def search_database(
    query: str = Field(description="検索クエリ文字列"),
    limit: int = Field(10, description="結果の最大数", ge=1, le=100)
) -> list:
    """提供されたクエリでデータベースを検索します。"""
    # 実装...
```

Fieldは、いくつかの検証およびドキュメント機能を提供します：
- `description`: パラメータの人間が読める説明（LLMに表示されます）
- `ge`/`gt`/`le`/`lt`: 以上/より大きい/以下/未満の制約
- `min_length`/`max_length`: 文字列またはコレクションの長さの制約
- `pattern`: 文字列検証用の正規表現パターン
- `default`: パラメータが省略された場合のデフォルト値

### Hiding Parameters from the LLM

<VersionBadge version="2.14.0" />

LLMに公開せずに実行時に値を注入する（`user_id`、認証情報、データベース接続など）には、`Depends()` を使用した依存性の注入（dependency injection）を使用します。`Depends()` を使用するパラメータは、Toolスキーマから自動的に除外されます：

```python
from fastmcp import FastMCP
from fastmcp.dependencies import Depends

mcp = FastMCP()

def get_user_id() -> str:
    return "user_123"  # 実行時に注入されます

@mcp.tool
def get_user_details(user_id: str = Depends(get_user_id)) -> str:
    # user_idはServerによって注入され、LLMからは提供されません
    return f"Details for {user_id}"
```

依存性の注入の詳細については、[Custom Dependencies](/servers/context#custom-dependencies)を参照してください。

## Return Values


FastMCPのToolは、**従来のコンテンツブロック**（テキストや画像など）と**構造化された出力**（機械可読なJSON）という2つの補完的な形式でデータを返すことができます。Return typeアノテーションを追加すると、FastMCPは構造化データを検証するための**出力スキーマ**を自動的に生成し、Clientが結果をPythonオブジェクトに逆シリアル化できるようにします。

これら3つの概念がどのように連携するかを理解します：

- **Return Values**: Python関数が返すもの（コンテンツブロックと構造化データの両方を決定します）
- **Structured Outputs**: 機械処理のために従来のコンテンツと一緒に送信されるJSONデータ
- **Output Schemas**: 構造化された出力フォーマットを記述および検証するJSON Schema宣言

以下のセクションでは、各概念について詳しく説明します。

### Content Blocks

FastMCPは、ToolのReturn valueを適切なMCPコンテンツブロックに自動的に変換します：

- **`str`**: `TextContent` として送信されます
- **`bytes`**: Base64エンコードされ、`BlobResourceContents` として（`EmbeddedResource` 内で）送信されます
- **`fastmcp.utilities.types.Image`**: `ImageContent` として送信されます
- **`fastmcp.utilities.types.Audio`**: `AudioContent` として送信されます
- **`fastmcp.utilities.types.File`**: Base64エンコードされた `EmbeddedResource` として送信されます
- **MCP SDK content blocks**: そのまま送信されます
- **上記のいずれかのリスト**: 上記のルールに従って各アイテムを変換します
- **`None`**: 空の応答になります

#### Media Helper Classes

FastMCPは、画像、音声、およびファイルを返すためのヘルパークラスを提供します。これらのクラスのいずれかを直接、またはリストの一部として返すと、FastMCPは自動的にそれを適切なMCPコンテンツブロックに変換します。たとえば、`fastmcp.utilities.types.Image` オブジェクトを返すと、FastMCPはそれを正しいMIMEタイプとbase64エンコーディングを持つMCP `ImageContent` ブロックに変換します。

```python
from fastmcp.utilities.types import Image, Audio, File

@mcp.tool
def get_chart() -> Image:
    """チャート画像を生成します。"""
    return Image(path="chart.png")

@mcp.tool
def get_multiple_charts() -> list[Image]:
    """複数のチャートを返します。"""
    return [Image(path="chart1.png"), Image(path="chart2.png")]
```

<Tip>
ヘルパークラスは、**直接**または**リスト**の一部として返された場合にのみ、自動的にMCPコンテンツブロックに変換されます。辞書のようなより複雑なコンテナの場合は、手動でMCP型に変換できます：

```python
# ✅ 自動変換
return Image(path="chart.png")
return [Image(path="chart1.png"), "text content"]

# ❌ 自動変換されません
return {"image": Image(path="chart.png")}

# ✅ ネストされた使用のための手動変換
return {"image": Image(path="chart.png").to_image_content()}
```
</Tip>

各ヘルパークラスは、`path=` または `data=` のいずれかを受け入れます（排他的）：
- **`path`**: ファイルパス（文字列またはPathオブジェクト） - 拡張子からMIMEタイプが検出されます
- **`data`**: 生のバイト - MIMEタイプのために `format=` パラメータが必要です
- **`format`**: オプションのフォーマットの上書き（例: "png", "wav", "pdf"）
- **`name`**: `data=` を使用する場合の `File` のオプションの名前
- **`annotations`**: コンテンツのオプションのMCPアノテーション

### Structured Output

<VersionBadge version="2.10.0" />

2025年6月18日のMCP仕様の更新により、Toolからデータを返す新しい方法である構造化コンテンツ（structured content）が[導入されました](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#structured-content)。構造化コンテンツ は、従来のコンテンツと一緒に送信されるJSONオブジェクトです。ToolがJSONオブジェクト表現を持つデータを返す場合、FastMCPは従来のコンテンツと一緒に構造化出力を自動的に作成します。これにより、ClientがネイティブのPythonオブジェクトに逆シリアル化できる機械可読なJSONデータが提供されます。

**自動構造化コンテンツのルール:**
- **オブジェクトのような結果**（`dict`、Pydanticモデル、データクラス） → 常に構造化コンテンツになります（出力スキーマがなくても）
- **オブジェクトではない結果**（`int`、`str`、`list`） → それらを検証/シリアル化するための出力スキーマがある場合にのみ構造化コンテンツになります
- **すべての結果** → 下位互換性のために常に従来のコンテンツブロックになります

<Note>
この自動的な動作により、Clientはオブジェクトのような戻り値に対して明示的な出力スキーマを必要とせずに、人間が読めるコンテンツと一緒に機械可読なデータを受け取ることができます。
</Note>

#### Dictionaries and Objects

Toolが辞書、データクラス、またはPydanticモデルを返す場合、FastMCPは自動的にそこから構造化コンテンツを作成します。構造化コンテンツには実際のオブジェクトデータが含まれており、Clientがネイティブオブジェクトに簡単に逆シリアル化できるようになります。

<CodeGroup>
```python Tool Definition
@mcp.tool
def get_user_data(user_id: str) -> dict:
    """ユーザーデータを取得します。"""
    return {"name": "Alice", "age": 30, "active": True}
```

```json MCP Result
{
  "content": [
    {
      "type": "text",
      "text": "{\n  \"name\": \"Alice\",\n  \"age\": 30,\n  \"active\": true\n}"
    }
  ],
  "structuredContent": {
    "name": "Alice",
    "age": 30,
    "active": true
  }
}
```
</CodeGroup>

#### Primitives and Collections

Toolがプリミティブ型（int、str、bool）またはコレクション（list、set）を返す場合、FastMCPが構造化コンテンツを生成するにはReturn typeアノテーションが必要です。アノテーションは、結果を検証およびシリアル化する方法をFastMCPに指示します。

型アノテーションがない場合、Toolは `content` のみを生成します：

<CodeGroup>
```python Tool Definition
@mcp.tool
def calculate_sum(a: int, b: int):
    """Return typeアノテーションなしで合計を計算します。"""
    return a + b  # 8を返します
```

```json MCP Result
{
  "content": [
    {
      "type": "text",
      "text": "8"
    }
  ]
}
```
</CodeGroup>

`-> int` のようなReturn typeアノテーションを追加すると、JSONスキーマは構造化出力のためにオブジェクト型のルートを必要とするため、FastMCPはプリミティブ値を `{"result": ...}` オブジェクトでラップすることによって `structuredContent` を生成します：

<CodeGroup>
```python Tool Definition
@mcp.tool
def calculate_sum(a: int, b: int) -> int:
    """Return typeアノテーション付きで合計を計算します。"""
    return a + b  # 8を返します
```

```json MCP Result
{
  "content": [
    {
      "type": "text",
      "text": "8"
    }
  ],
  "structuredContent": {
    "result": 8
  }
}
```
</CodeGroup>

#### Typed Models

Return typeアノテーションは、JSONスキーマに変換できる任意の型で機能します。データクラスとPydanticモデルは、FastMCPがそれらのフィールド定義を抽出して詳細なスキーマを作成するため、特に便利です。

<CodeGroup>
```python Tool Definition
from dataclasses import dataclass
from fastmcp import FastMCP

mcp = FastMCP()

@dataclass
class Person:
    name: str
    age: int
    email: str

@mcp.tool
def get_user_profile(user_id: str) -> Person:
    """ユーザーのプロフィール情報を取得します。"""
    return Person(
        name="Alice",
        age=30,
        email="alice@example.com",
    )
```

```json Generated Output Schema
{
  "properties": {
    "name": {"title": "Name", "type": "string"},
    "age": {"title": "Age", "type": "integer"},
    "email": {"title": "Email", "type": "string"}
  },
  "required": ["name", "age", "email"],
  "title": "Person",
  "type": "object"
}
```

```json MCP Result
{
  "content": [
    {
      "type": "text",
      "text": "{\"name\": \"Alice\", \"age\": 30, \"email\": \"alice@example.com\"}"
    }
  ],
  "structuredContent": {
    "name": "Alice",
    "age": 30,
    "email": "alice@example.com"
  }
}
```
</CodeGroup>

`Person` データクラスは、期待されるフォーマットを記述する出力スキーマ（2番目のタブ）になります。実行されると、Clientは `content` と `structuredContent` の両方のフィールドを持つ結果（3番目のタブ）を受け取ります。

### Output Schemas

<VersionBadge version="2.10.0" />

2025年6月18日のMCP仕様の更新により、Toolの期待される出力フォーマットを記述する新しい方法である出力スキーマ（output schemas）が[導入されました](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#output-schema)。出力スキーマが提供されている場合、Toolはスキーマに一致する構造化出力を返す*必要があります*。

関数にReturn typeアノテーションを追加すると、FastMCPは期待される出力フォーマットを記述するJSONスキーマを自動的に生成します。これらのスキーマは、MCP Clientが受信した構造化データを理解し、検証するのに役立ちます。

#### Primitive Type Wrapping

プリミティブなReturn type（`int`、`str`、`bool` など）の場合、FastMCPは自動的に結果を `"result"` キーの下にラップして、有効な構造化出力を作成します：

<CodeGroup>
```python Primitive Return Type
@mcp.tool
def calculate_sum(a: int, b: int) -> int:
    """2つの数値を足し合わせます。"""
    return a + b
```

```json Generated Schema (Wrapped)
{
  "type": "object",
  "properties": {
    "result": {"type": "integer"}
  },
  "x-fastmcp-wrap-result": true
}
```

```json Structured Output
{
  "result": 8
}
```
</CodeGroup>

#### Manual Schema Control

カスタムの `output_schema` を提供することで、自動生成されたスキーマを上書きできます：

```python
@mcp.tool(output_schema={
    "type": "object",
    "properties": {
        "data": {"type": "string"},
        "metadata": {"type": "object"}
    }
})
def custom_schema_tool() -> dict:
    """カスタム出力スキーマを持つTool。"""
    return {"data": "Hello", "metadata": {"version": "1.0"}}
```

スキーマの生成は、基本型、コレクション、ユニオン型、Pydanticモデル、TypedDict構造、データクラスなど、最も一般的な型で機能します。

<Warning>
**重要な制約**:
- 出力スキーマはオブジェクト型（`"type": "object"`）である必要があります。
- 出力スキーマを提供する場合、Toolはそれに一致する構造化出力を返す**必要があります**。
- ただし、出力スキーマなしで構造化出力を提供することは可能です（`ToolResult` を使用）。
</Warning>

### ToolResult and Metadata

Toolの応答を完全に制御するには、`ToolResult` オブジェクトを返します。これにより、従来のコンテンツ、構造化データ、メタデータなど、Toolの出力のすべての側面を明示的に制御できます。

```python
from fastmcp.tools.tool import ToolResult
from mcp.types import TextContent

@mcp.tool
def advanced_tool() -> ToolResult:
    """出力を完全に制御できるTool。"""
    return ToolResult(
        content=[TextContent(type="text", text="人間が読める要約")],
        structured_content={"data": "value", "count": 42},
        meta={"execution_time_ms": 145}
    )
```

`ToolResult` は3つのフィールドを受け入れます：

**`content`** - Clientがユーザーに表示する従来のMCPコンテンツブロック。文字列（自動的に `TextContent` に変換されます）、MCPコンテンツブロックのリスト、または任意のシリアル化可能な値（JSON文字列に変換されます）を指定できます。`content` または `structured_content` の少なくとも1つを提供する必要があります。

```python
# 単純な文字列
ToolResult(content="Hello, world!")

# コンテンツブロックのリスト
ToolResult(content=[
    TextContent(type="text", text="Result: 42"),
    ImageContent(type="image", data="base64...", mimeType="image/png")
])
```

**`structured_content`** - Toolの出力スキーマに一致する構造化データを含む辞書。これにより、Clientは結果をプログラムで処理できるようになります。`structured_content` を提供する場合、それは辞書または `None` である必要があります。`structured_content` のみが提供された場合、それは `content` としても使用されます（JSON文字列に変換されます）。

```python
ToolResult(
    content="3人のユーザーが見つかりました",
    structured_content={"users": [{"name": "Alice"}, {"name": "Bob"}]}
)
```

**`meta`**
<VersionBadge version="2.13.1" />
Tool実行に関するランタイムメタデータ。パフォーマンスメトリクス、デバッグ情報、またはコンテンツや構造化出力に属さないClient固有のデータにこれを使用します。

```python
ToolResult(
    content="分析が完了しました",
    structured_content={"result": "positive"},
    meta={
        "execution_time_ms": 145,
        "model_version": "2.1",
        "confidence": 0.95
    }
)
```

<Note>
`ToolResult` の `meta` フィールドは、Tool実行に関するランタイムメタデータ（実行時間、パフォーマンスメトリクスなど）用です。これは、Tool定義自体に関する静的メタデータを提供する `@mcp.tool(meta={...})` の `meta` パラメータとは異なります。
</Note>

`ToolResult` を返す場合、完全に制御できます - FastMCPはデータを自動的にラップしたり変換したりしません。`ToolResult` は、出力スキーマの有無にかかわらず返すことができます。

### Custom Serialization

カスタムのシリアル化（YAML、Markdownテーブル、または特殊なフォーマットなど）が必要な場合は、シリアル化されたコンテンツと共に `ToolResult` を返します。これにより、シリアル化が明示的になり、Toolのコードで可視化されます：

```python
import yaml
from fastmcp import FastMCP
from fastmcp.tools.tool import ToolResult

mcp = FastMCP("MyServer")

@mcp.tool
def get_config() -> ToolResult:
    """設定をYAMLとして返します。"""
    data = {"api_key": "abc123", "debug": True, "rate_limit": 100}
    return ToolResult(
        content=yaml.dump(data, sort_keys=False),
        structured_content=data
    )
```

<Tip>
複数のTool間で再利用可能なシリアル化を行うには、`ToolResult` を返すラッパーDecoratorを作成します。これにより、シリアライザーを他の動作（ロギング、検証、キャッシング）と組み合わせることができ、Tool定義でシリアル化を可視化できます。完全な 実装については、[examples/custom_tool_serializer_decorator.py](https://github.com/PrefectHQ/fastmcp/blob/main/examples/custom_tool_serializer_decorator.py) を参照してください。
</Tip>

## Error Handling

<VersionBadge version="2.4.1" />

Toolでエラーが発生した場合、標準のPython例外（`ValueError`、`TypeError`、`FileNotFoundError`、カスタム例外など）またはFastMCPの `ToolError` を発生させることができます。

デフォルトでは、すべての例外（その詳細を含む）がログに記録され、ClientのLLMに送り返されるMCPエラー応答に変換されます。これは、LLMが失敗を理解し、適切に反応するのに役立ちます。

セキュリティ上の理由から内部エラーの詳細をマスクしたい場合は、以下の方法があります：

1. `FastMCP` インスタンスを作成する際に `mask_error_details=True` パラメータを使用する：
```python
mcp = FastMCP(name="SecureServer", mask_error_details=True)
```

2. または、`ToolError` を使用して、Clientに送信されるエラー情報を明示的に制御する：
```python
from fastmcp import FastMCP
from fastmcp.exceptions import ToolError

@mcp.tool
def divide(a: float, b: float) -> float:
    """aをbで割ります。"""

    if b == 0:
        # ToolErrorからのエラーメッセージは、mask_error_detailsの設定に関係なく、
        # 常にClientに送信されます
        raise ToolError("ゼロ除算は許可されていません。")

    # mask_error_details=True の場合、このメッセージはマスクされます
    if not isinstance(a, (int, float)) or not isinstance(b, (int, float)):
        raise TypeError("両方のArgumentは数値である必要があります。")

    return a / b
```

`mask_error_details=True` の場合、`ToolError` からのエラーメッセージのみに詳細が含まれ、他の例外は一般的なメッセージに変換されます。

## Timeouts

<VersionBadge version="3.0.0" />

Toolは、実行にかかる時間を制限するために `timeout` パラメータを指定できます。タイムアウトを超過すると、ClientはMCPエラーを受け取り、Toolは処理を停止します。これにより、リソースをブロックしたり、Clientを無期限に待たせたりする可能性のある 、予期せず遅い操作からServerを保護します。

```python
from fastmcp import FastMCP

mcp = FastMCP()

@mcp.tool(timeout=30.0)
async def fetch_data(url: str) -> dict:
    """30秒のタイムアウトでデータを取得します。"""
    # これに30秒以上かかる場合、
    # ClientはMCPエラーを受け取ります
    ...
```

タイムアウトは浮動小数点数として秒単位で指定されます。Toolがタイムアウトを超過すると、FastMCPはコード `-32000` と、どのToolがタイムアウトし、どのくらい実行されたかを示すメッセージを含むMCPエラーを返します。同期Toolと非同期Toolの両方がタ イムアウトをサポートしています。同期関数はスレッドプールで実行されるため、実行モデルに関係なく、操作全体にタイムアウトが適用されます。

<Note>
Toolは明示的にタイムアウトをオプトインする必要があります。Serverレベルのデフォルトのタイムアウト設定はありません。
</Note>

### Timeouts vs Background Tasks

タイムアウトは**フォアグラウンド実行**（Clientのリクエストに応答してToolが直接実行される場合）に適用されます。ネットワークの問題、リソースの競合、またはその他の過渡的な問題によって予期せずハングするToolからServerを保護します。

<Warning>
`timeout` パラメータはバックグラウンドタスクには適用され**ません**。Toolがバックグラウンドタスク（`task=True`）として実行される場合、実行はDocketワーカーで行われ、FastMCPのタイムアウトは適用されません。

タスクのタイムアウトについては、関数のシグネチャで直接Docketの `Timeout` 依存関係を使用してください：

```python
from datetime import timedelta
from docket import Timeout

@mcp.tool(task=True)
async def long_running_task(
    data: str,
    timeout: Timeout = Timeout(timedelta(minutes=10))
) -> str:
    """Docketによって適用される10分のタイムアウトを持つタスク。"""
    ...
```

タスクのタイムアウトと再試行の詳細については、[Docketのドキュメント](https://chrisguidry.github.io/docket/dependencies/#task-timeouts)を参照してください。
</Warning>

Toolがタイムアウトすると、FastMCPはタスクモードを提案する警告をログに記録します。長時間実行されることがわかっている操作については、代わりに `task=True` を使用してください。バックグラウンドタスクは分散ワーカーに作業をオフロードし、Client が進行状況をポーリングできるようにします。

## Component Visibility

<VersionBadge version="3.0.0" />

Serverレベルの有効化制御を使用して、Clientに対してどのToolを有効にするかを制御できます。無効化されたToolは `list_tools` に表示されず、呼び出すこともできません。

```python
from fastmcp import FastMCP

mcp = FastMCP("MyServer")

@mcp.tool(tags={"admin"})
def admin_action() -> str:
    """管理者専用のアクション。"""
    return "Done"

@mcp.tool(tags={"public"})
def public_action() -> str:
    """パブリックなアクション。"""
    return "Done"

# キーによって特定のToolを無効にする
mcp.disable(keys={"tool:admin_action"})

# タグによってToolを無効にする
mcp.disable(tags={"admin"})

# または許可リストモードを使用する - 特定のタグを持つToolのみを有効にする
mcp.enable(tags={"public"}, only=True)
```

キーのフォーマット、タグベースのフィルタリング、プロバイダーレベルの制御を含む完全な可視性制御APIについては、[Visibility](/servers/visibility)を参照してください。

## MCP Annotations

<VersionBadge version="2.2.7" />

FastMCPでは、アノテーションを通じてToolに特化したメタデータを追加できます。これらのアノテーションは、LLMのPromptのトークンコンテキストを消費することなく、Toolがどのように動作するかをClientアプリケーションに伝達します。

アノテーションは、Clientアプリケーションでいくつかの目的を果たします：
- 表示目的のためのユーザーフレンドリーなタイトルの追加
- Toolがデータやシステムを変更するかどうかの指示
- Toolの安全プロファイル（破壊的か非破壊的か）の記述
- Toolが外部システムと対話するかどうかのシグナル

`@mcp.tool` Decoratorの `annotations` パラメータを使用して、Toolにアノテーションを追加できます：

```python
@mcp.tool(
    annotations={
        "title": "Calculate Sum",
        "readOnlyHint": True,
        "openWorldHint": False
    }
)
def calculate_sum(a: float, b: float) -> float:
    """2つの数値を足し合わせます。"""
    return a + b
```

FastMCPは以下の標準アノテーションをサポートしています：

| Annotation | Type | Default | Purpose |
| :--------- | :--- | :------ | :------ |
| `title` | string | - | ユーザーインターフェース用の表示名 |
| `readOnlyHint` | boolean | false | Toolが変更を加えずに読み取りのみを行うかどうかを示します |
| `destructiveHint` | boolean | true | 読み取り専用ではないToolの場合、変更が破壊的であるかどうかをシグナルします |
| `idempotentHint` | boolean | false | 繰り返しの同一の呼び出しが単一の呼び出しと同じ効果を持つかどうかを示します |
| `openWorldHint` | boolean | true | Toolが外部システムと対話するかどうかを指定します |

アノテーションはより良いユーザーエクスペリエンスを作るのに役立ちますが、助言的なヒントとして扱われるべきであることを覚えておいてください。これらはClientアプリケーションが適切なUI要素と安全制御を提示するのに役立ちますが、それ自体でセキュ リティ境界を強制するものではありません。常に、アノテーションがToolの実際の動作を正確に表すようにすることに焦点を当ててください。

### Using Annotation Hints

ClaudeやChatGPTのようなMCP Clientは、アノテーションのヒントを使用して、確認のPromptをいつスキップするか、およびユーザーにToolをどのように提示するかを決定します。最も一般的に使用されるヒントは `readOnlyHint` であり、これはToolが変更を加えずにデータのみを読み取ることをシグナルします。

**読み取り専用のTool**は、以下の方法でユーザーエクスペリエンスを向上させます：
- 安全な操作に対する確認のPromptをスキップする
- セキュリティ上の懸念なしに幅広いアクセスを許可する
- より積極的なバッチ処理とキャッシングを可能にする

Toolが状態を変更せずにデータを取得したり、計算を実行したり、ステータスを確認したりする場合は、読み取り専用としてマークします：

```python
from fastmcp import FastMCP
from mcp.types import ToolAnnotations

mcp = FastMCP("Data Server")

@mcp.tool(annotations={"readOnlyHint": True})
def get_user(user_id: str) -> dict:
    """IDによってユーザー情報を取得します。"""
    return {"id": user_id, "name": "Alice"}

@mcp.tool(
    annotations=ToolAnnotations(
        readOnlyHint=True,
        idempotentHint=True,  # 繰り返しの呼び出しでも同じ結果
        openWorldHint=False   # 内部データのみ
    )
)
def search_products(query: str) -> list[dict]:
    """製品カタログを検索します。"""
    return [{"id": 1, "name": "Widget", "price": 29.99}]

# 書き込み操作 - readOnlyHintなし
@mcp.tool()
def update_user(user_id: str, name: str) -> dict:
    """ユーザー情報を更新します。"""
    return {"id": user_id, "name": name, "updated": True}

@mcp.tool(annotations={"destructiveHint": True})
def delete_user(user_id: str) -> dict:
    """ユーザーアカウントを完全に削除します。"""
    return {"deleted": user_id}
```

データベースへの書き込み、通知の送信、Resourceの作成/更新/削除、またはワークフローのトリガーを行うToolの場合は、`readOnlyHint` を省略するか、`False` に設定します。元に戻せない操作には `destructiveHint=True` を使用します。

Client固有の動作：
- **ChatGPT**: チャットモードでの読み取り専用Toolの確認Promptをスキップします（[ChatGPT integration](/integrations/chatgpt)を参照）
- **Claude**: ヒントを使用してToolの安全プロファイルを理解し、より良い実行の決定を下します

## Notifications

<VersionBadge version="2.9.1" />

FastMCPは、Toolが追加、削除、有効化、または無効化されたときに、接続されているClientに自動的に `notifications/tools/list_changed` 通知を送信します。これにより、Clientは変更を手動でポーリングすることなく、現在のToolセットを最新の状態に保つことができます。

```python
@mcp.tool
def example_tool() -> str:
    return "Hello!"

# これらの操作は通知をトリガーします：
mcp.add_tool(example_tool)              # tools/list_changed 通知を送信します
mcp.disable(keys={"tool:example_tool"}) # tools/list_changed 通知を送信します
mcp.enable(keys={"tool:example_tool"})  # tools/list_changed 通知を送信します
mcp.local_provider.remove_tool("example_tool")  # tools/list_changed 通知を送信します
```

通知は、これらの操作がアクティブなMCPリクエストコンテキスト内（例：Tool内や他のMCP操作内から呼び出された場合）で発生した場合にのみ送信されます。Serverの初期化中に実行された操作は通知をトリガーしません。

Clientは、[message handler](/clients/notifications)を使用してこれらの通知を処理し、Toolリストを自動的に更新したり、インターフェースを更新したりできます。

## Accessing the MCP Context

Toolは、`Context` オブジェクトを通じて、ロギング、Resourceの読み取り、進行状況の報告などのMCP機能にアクセスできます。これを使用するには、型ヒント `Context` を持つパラメータをTool関数に追加します。

```python
from fastmcp import FastMCP, Context

mcp = FastMCP(name="ContextDemo")

@mcp.tool
async def process_data(data_uri: str, ctx: Context) -> dict:
    """進行状況の報告を伴うResourceからのデータを処理します。"""
    await ctx.info(f"{data_uri} からのデータを処理しています")

    # Resourceを読み取る
    resource = await ctx.read_resource(data_uri)
    data = resource[0].content if resource else ""

    # 進行状況を報告する
    await ctx.report_progress(progress=50, total=100)

    # 助けを求めるためのClientのLLMへのリクエスト例
    summary = await ctx.sample(f"これを10語で要約してください: {data[:200]}")

    await ctx.report_progress(progress=100, total=100)
    return {
        "length": len(data),
        "summary": summary.text
    }
```

Contextオブジェクトは以下へのアクセスを提供します：

- **ロギング**: `ctx.debug()`, `ctx.info()`, `ctx.warning()`, `ctx.error()`
- **進行状況の報告**: `ctx.report_progress(progress, total)`
- **Resourceへのアクセス**: `ctx.read_resource(uri)`
- **LLMサンプリング**: `ctx.sample(...)`
- **リクエスト情報**: `ctx.request_id`, `ctx.client_id`

Contextオブジェクトとそのすべての機能の完全なドキュメントについては、[Context documentation](/servers/context)を参照してください。

## Server Behavior

### Duplicate Tools

<VersionBadge version="2.1.0" />

同じ名前の複数のToolを登録しようとした場合のFastMCP Serverの動作を制御できます。これは、`FastMCP` インスタンスを作成する際の `on_duplicate_tools` Argumentを使用して設定します。

```python
from fastmcp import FastMCP

mcp = FastMCP(
    name="StrictServer",
    # 重複するTool名の動作を設定する
    on_duplicate_tools="error"
)

@mcp.tool
def my_tool(): return "Version 1"

# 'my_tool' がすでに存在し、on_duplicate_tools が "error" に設定されているため、
# これは ValueError を発生させます。
# @mcp.tool
# def my_tool(): return "Version 2"
```

重複時の動作オプションは以下の通りです：

-   `"warn"` (デフォルト): 警告をログに記録し、新しいToolが古いToolを置き換えます。
-   `"error"`: `ValueError` を発生させ、重複登録を防ぎます。
-   `"replace"`: 既存のToolを新しいToolに静かに置き換えます。
-   `"ignore"`: 元のToolを保持し、新しい登録の試みを無視します。

### Removing Tools

<VersionBadge version="2.3.4" />

[local provider](/servers/providers/local)を通じて、Serverから動的にToolを削除できます：

```python
from fastmcp import FastMCP

mcp = FastMCP(name="DynamicToolServer")

@mcp.tool
def calculate_sum(a: int, b: int) -> int:
    """2つの数値を足し合わせます。"""
    return a + b

mcp.local_provider.remove_tool("calculate_sum")
```
