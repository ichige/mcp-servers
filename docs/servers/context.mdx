FastMCPの[Tool](/servers/tools)、[Resource](/servers/resources)、Resourceテンプレート、または[Prompt](/servers/prompts)を定義する際、関数が基盤となるMCPセッションと対話したり、高度なServer機能にアクセスしたりする必要がある場合があります。FastMCPは、この目的のために`Context`オブジェクトを提供しています。

<Note>
Contextには、FastMCPの依存性注入（Dependency Injection）システムを通じてアクセスします。HTTPリクエスト、アクセストークン、カスタム依存関係など、その他の注入可能な値については、[Dependency Injection](/servers/dependency-injection)を参照してください。
</Note>

## Contextとは？

`Context`オブジェクトは、関数内でMCP機能にアクセスするためのクリーンなインターフェースを提供します。これには以下が含まれます。

- **ロギング**: デバッグ、情報、警告、エラーメッセージをClientに送り返します。
- **進捗報告**: 実行時間の長い操作の進捗状況をClientに更新します。
- **Resourceアクセス**: Serverに登録されたResourceのリスト取得やデータの読み取りを行います。
- **Promptアクセス**: Serverに登録されたPromptのリスト取得や取得を行います。
- **LLMサンプリング**: 提供されたメッセージに基づいてテキストを生成するよう、ClientのLLMにリクエストします。
- **ユーザー入力の要求 (User Elicitation)**: Tool実行中にユーザーに構造化された入力を要求します。
- **セッション状態**: MCPセッション内のリクエスト間で永続化されるデータを保存します。
- **セッションの可視性**: 現在のセッションに対して[どのコンポーネントを表示するかを制御](/servers/visibility#per-session-visibility)します。
- **リクエスト情報**: 現在のリクエストに関するメタデータにアクセスします。
- **Serverアクセス**: 必要に応じて、基盤となるFastMCP Serverインスタンスにアクセスします。

## Contextへのアクセス

<VersionBadge version="2.14" />

Contextにアクセスする推奨される方法は、`CurrentContext()`依存関係を使用することです。

```python {1, 6}
from fastmcp import FastMCP
from fastmcp.dependencies import CurrentContext
from fastmcp.server.context import Context

mcp = FastMCP(name="Context Demo")

@mcp.tool
async def process_file(file_uri: str, ctx: Context = CurrentContext()) -> str:
    """ロギングとResourceアクセスのためにContextを使用して、ファイルを処理します。"""
    await ctx.info(f"Processing {file_uri}")
    return "Processed file"
```

これはTool、Resource、Promptで機能します。

```python
from fastmcp import FastMCP
from fastmcp.dependencies import CurrentContext
from fastmcp.server.context import Context

mcp = FastMCP(name="Context Demo")

@mcp.resource("resource://user-data")
async def get_user_data(ctx: Context = CurrentContext()) -> dict:
    await ctx.debug("Fetching user data")
    return {"user_id": "example"}

@mcp.prompt
async def data_analysis_request(dataset: str, ctx: Context = CurrentContext()) -> str:
    return f"Please analyze the following dataset: {dataset}"
```

**重要なポイント:**

- 依存関係のパラメータはMCPスキーマから自動的に除外されるため、Clientから見えることはありません。
- Contextのメソッドは非同期（async）であるため、通常は関数も非同期にする必要があります。
- **各MCPリクエストは新しいContextオブジェクトを受け取ります。** Contextは単一のリクエストにスコープされています。あるリクエストで設定された状態やデータは、後続のリクエストでは利用できません。
- Contextはリクエストの処理中のみ利用可能です。リクエストの外部でContextのメソッドを使用しようとすると、エラーが発生します。

### レガシーな型ヒントによる注入

下位互換性のため、`Context`の型ヒントを持つパラメータを追加するだけでもContextにアクセスできます。FastMCPは自動的にContextインスタンスを注入します。

```python {1, 6}
from fastmcp import FastMCP, Context

mcp = FastMCP(name="Context Demo")

@mcp.tool
async def process_file(file_uri: str, ctx: Context) -> str:
    """ロギングとResourceアクセスのためにContextを使用して、ファイルを処理します。"""
    # Contextは型ヒントに基づいて自動的に注入されます
    return "Processed file"
```

このアプローチは、引き続きTool、Resource、Promptで機能します。パラメータ名は重要ではなく、`Context`という型ヒントのみが重要です。型ヒントはユニオン（`Context | None`）にしたり、`Annotated[]`を使用したりすることもできます。

### `get_context()` 関数経由

<VersionBadge version="2.2.11" />

関数呼び出しの深い階層にネストされたコードなど、パラメータを通じてContextを渡すのが不便な場合は、`get_context()`を使用して、リクエストの実行フロー内のどこからでもアクティブなContextを取得できます。

```python {2,9}
from fastmcp import FastMCP
from fastmcp.server.dependencies import get_context

mcp = FastMCP(name="Dependency Demo")

# Contextを必要とするが、パラメータとして受け取らないユーティリティ関数
async def process_data(data: list[float]) -> dict:
    # アクティブなContextを取得 - リクエスト内で呼び出された場合のみ機能します
    ctx = get_context()
    await ctx.info(f"Processing {len(data)} data points")

@mcp.tool
async def analyze_dataset(dataset_name: str) -> dict:
    # 内部でContextを使用するユーティリティ関数を呼び出します
    data = load_data(dataset_name)
    await process_data(data)
```

**重要な注意事項:**

- `get_context()`関数は、Serverリクエストのコンテキスト内でのみ使用する必要があります。リクエストの外部で呼び出すと、`RuntimeError`が発生します。
- `get_context()`関数はServer専用であり、Clientコードでは使用しないでください。

## Contextの機能

FastMCPは、Contextオブジェクトを通じていくつかの高度な機能を提供します。各機能には、包括的な例とベストプラクティスを含む専用のドキュメントがあります。

### ロギング

関数の実行状況を可視化するために、デバッグ、情報、警告、エラーメッセージをMCP Clientに送り返します。

```python
await ctx.debug("Starting analysis")
await ctx.info(f"Processing {len(data)} items") 
await ctx.warning("Deprecated parameter used")
await ctx.error("Processing failed")
```

完全なドキュメントと例については、[Server Logging](/servers/logging)を参照してください。

### Clientへの入力要求 (Client Elicitation)

<VersionBadge version="2.10.0" />

Tool実行中にClientに構造化された入力を要求し、インタラクティブなワークフローと段階的な情報開示を可能にします。これは2025年6月18日のMCP仕様における新機能です。

```python
result = await ctx.elicit("Enter your name:", response_type=str)
if result.action == "accept":
    name = result.data
```

詳細な例とサポートされているレスポンスの型については、[User Elicitation](/servers/elicitation)を参照してください。

### LLMサンプリング

<VersionBadge version="2.0.0" />

提供されたメッセージに基づいてテキストを生成するようClientのLLMにリクエストします。これは、Tool内でAI機能を活用するのに役立ちます。

```python
response = await ctx.sample("Analyze this data", temperature=0.7)
```

包括的な使用方法と高度なテクニックについては、[LLM Sampling](/servers/sampling)を参照してください。

### 進捗報告

実行時間の長い操作の進捗状況をClientに更新し、プログレスインジケーターの表示やユーザーエクスペリエンスの向上を可能にします。

```python
await ctx.report_progress(progress=50, total=100)  # 50% 完了
```

詳細なパターンと例については、[Progress Reporting](/servers/progress)を参照してください。

### Resourceアクセス

FastMCP Serverに登録されたResourceのリスト取得やデータの読み取りを行い、ファイル、設定、または動的コンテンツへのアクセスを可能にします。

```python
# 利用可能なResourceをリストアップします
resources = await ctx.list_resources()

# 特定のResourceを読み取ります
content_list = await ctx.read_resource("resource://config")
content = content_list[0].content
```

**メソッドシグネチャ:**
- **`ctx.list_resources() -> list[MCPResource]`**: <VersionBadge version="2.13.0" /> 利用可能なすべてのResourceのリストを返します。
- **`ctx.read_resource(uri: str | AnyUrl) -> list[ReadResourceContents]`**: Resourceコンテンツのパーツのリストを返します。

### Promptアクセス

<VersionBadge version="2.13.0" />

FastMCP Serverに登録されたPromptのリスト取得や取得を行い、Toolやミドルウェアがプログラムから利用可能なPromptを発見して使用できるようにします。

```python
# 利用可能なPromptをリストアップします
prompts = await ctx.list_prompts()

# 引数を指定して特定のPromptを取得します
result = await ctx.get_prompt("analyze_data", {"dataset": "users"})
messages = result.messages
```

**メソッドシグネチャ:**
- **`ctx.list_prompts() -> list[MCPPrompt]`**: 利用可能なすべてのPromptのリストを返します。
- **`ctx.get_prompt(name: str, arguments: dict[str, Any] | None = None) -> GetPromptResult`**: オプションの引数を指定して特定のPromptを取得します。

### セッション状態

<VersionBadge version="3.0.0" />

同じMCPセッション内の複数のリクエスト間で永続化されるデータを保存します。セッション状態はClientのセッションによって自動的にキー付けされ、異なるClient間の分離が保証されます。

```python
from fastmcp import FastMCP, Context

mcp = FastMCP("stateful-app")

@mcp.tool
async def increment_counter(ctx: Context) -> int:
    """Tool呼び出し間で永続化されるカウンターをインクリメントします。"""
    count = await ctx.get_state("counter") or 0
    await ctx.set_state("counter", count + 1)
    return count + 1

@mcp.tool
async def get_counter(ctx: Context) -> int:
    """現在のカウンター値を取得します。"""
    return await ctx.get_state("counter") or 0
```

各Clientセッションは独自の分離された状態を持ちます。2つの異なるClientが`increment_counter`を呼び出した場合、それぞれが独自のカウンターを持つことになります。

**メソッドシグネチャ:**
- **`await ctx.set_state(key, value, *, serializable=True)`**: セッション状態に値を保存します。
- **`await ctx.get_state(key)`**: 値を取得します（見つからない場合はNoneを返します）。
- **`await ctx.delete_state(key)`**: セッション状態から値を削除します。

<Note>
状態メソッドは非同期（async）であり、`await`が必要です。メモリの無制限な増加を防ぐため、状態は1日後に期限切れになります。
</Note>

#### シリアライズ不可能な値

デフォルトでは、リクエスト間で永続化できるように、状態の値はJSONシリアライズ可能（辞書、リスト、文字列、数値など）である必要があります。HTTP Clientやデータベース接続などのシリアライズ不可能な値の場合は、`serializable=False`を渡します。

```python
@mcp.tool
async def my_tool(ctx: Context) -> str:
    # このオブジェクトはJSONシリアライズできません
    client = SomeHTTPClient(base_url="https://api.example.com")
    await ctx.set_state("client", client, serializable=False)

    # 同じリクエスト内で後で取得します
    client = await ctx.get_state("client")
    return await client.fetch("/data")
```

`serializable=False`で保存された値は、現在のMCPリクエスト（単一のTool呼び出し、Resource読み取り、またはPromptレンダリング）の間のみ有効です。セッション内の後続のリクエストでは利用できません。

#### カスタムストレージバックエンド

デフォルトでは、セッション状態は単一Serverのデプロイメントに適したインメモリストアを使用します。分散デプロイメントやサーバーレスデプロイメントの場合は、カスタムストレージバックエンドを提供します。

```python
from key_value.aio.stores.redis import RedisStore

# 分散状態にRedisを使用します
mcp = FastMCP("distributed-app", session_state_store=RedisStore(...))
```

[py-key-value-aio](https://github.com/strawgate/py-key-value)の`AsyncKeyValue`プロトコルと互換性のある任意のバックエンドが機能します。Redis、DynamoDB、MongoDBなどのその他のオプションについては、[Storage Backends](/servers/storage-backends)を参照してください。

#### 初期化中の状態

`on_initialize`ミドルウェア中に設定された状態は、同じセッションオブジェクト（STDIO、SSE、単一ServerのHTTP）を使用する場合、後続のTool呼び出しに永続化されます。異なるマシンが初期化とTool呼び出しを処理する分散/サーバーレスHTTPデプロイメントの場合、状態は`mcp-session-id`ヘッダーによって分離されます。

### セッションの可視性

<VersionBadge version="3.0.0" />

Toolは、`ctx.enable_components()`、`ctx.disable_components()`、および`ctx.reset_visibility()`を使用して、現在のセッションに対してどのコンポーネントを表示するかをカスタマイズできます。これらのメソッドは、呼び出し元のセッションにのみ影響を与える可視性ルールを適用し、他のセッションは変更しません。完全なドキュメント、フィルター条件、および名前空間のアクティブ化などのパターンについては、[Per-Session Visibility](/servers/visibility#per-session-visibility)を参照してください。

### 変更通知

<VersionBadge version="3.0.0" />

FastMCPは、コンポーネント（Tool、Resource、Promptなど）が追加、削除、有効化、または無効化されたときに、リスト変更通知を自動的に送信します。これらの通知を手動でトリガーする必要があるまれなケースでは、Contextの通知メソッドを使用できます。

```python
import mcp.types

@mcp.tool
async def custom_tool_management(ctx: Context) -> str:
    """カスタムTool変更後の手動通知の例。"""
    await ctx.send_notification(mcp.types.ToolListChangedNotification())
    await ctx.send_notification(mcp.types.ResourceListChangedNotification())
    await ctx.send_notification(mcp.types.PromptListChangedNotification())
    return "Notifications sent"
```

これらのメソッドは主にFastMCPの自動通知システムによって内部的に使用されるため、ほとんどのユーザーは直接呼び出す必要はありません。

### FastMCP Server

基盤となるFastMCP Serverインスタンスにアクセスするには、`ctx.fastmcp`プロパティを使用できます。

```python
@mcp.tool
async def my_tool(ctx: Context) -> None:
    # FastMCP Serverインスタンスにアクセスします
    server_name = ctx.fastmcp.name
    ...
```

### Transport

<VersionBadge version="3.0.0" />

`ctx.transport`プロパティは、Serverの実行に使用されているTransportを示します。これは、ServerがSTDIO、SSE、またはStreamable HTTPのいずれで実行されているかに応じて、Toolの動作を変える必要がある場合に便利です。たとえば、STDIO経由ではより短いレスポンスを返したり、Transportの特性に基づいてタイムアウトの動作を調整したりすることができます。

TransportのタイプはServerの起動時に一度設定され、Serverの存続期間中は一定に保たれます。Serverコンテキストの外部（たとえば、ユニットテストやMCPリクエストの外部でコードを実行する場合）で呼び出された場合は、`None`を返します。

```python
from fastmcp import FastMCP, Context

mcp = FastMCP("example")

@mcp.tool
def connection_info(ctx: Context) -> str:
    if ctx.transport == "stdio":
        return "Connected via STDIO"
    elif ctx.transport == "sse":
        return "Connected via SSE"
    elif ctx.transport == "streamable-http":
        return "Connected via Streamable HTTP"
    else:
        return "Transport unknown"
```

**プロパティシグネチャ:** `ctx.transport -> Literal["stdio", "sse", "streamable-http"] | None`

### MCPリクエスト

現在のリクエストとClientに関するメタデータにアクセスします。

```python
@mcp.tool
async def request_info(ctx: Context) -> dict:
    """現在のリクエストに関する情報を返します。"""
    return {
        "request_id": ctx.request_id,
        "client_id": ctx.client_id or "Unknown client"
    }
```

**利用可能なプロパティ:**

- **`ctx.request_id -> str`**: 現在のMCPリクエストの一意のIDを取得します。
- **`ctx.client_id -> str | None`**: 初期化時に提供されている場合、リクエストを行っているClientのIDを取得します。
- **`ctx.session_id -> str`**: セッションベースのデータ共有のためのMCPセッションIDを取得します。MCPセッションがまだ確立されていない場合は、`RuntimeError`が発生します。

#### リクエストコンテキストの可用性

<VersionBadge version="2.13.1" />

`ctx.request_context`プロパティは、基盤となるMCPリクエストコンテキストへのアクセスを提供しますが、MCPセッションがまだ確立されていない場合は`None`を返します。これは通常、以下の場合に発生します。

- MCPハンドシェイクが完了する前の`on_request`フックでのミドルウェア実行中
- Client接続の初期化フェーズ中

MCPリクエストコンテキストはHTTPリクエストとは異なります。HTTP Transportの場合、MCPセッションがまだ確立されていなくても、HTTPリクエストデータが利用できる場合があります。

リクエストコンテキストが利用できない可能性がある状況で安全にアクセスするには、次のようにします。

```python
from fastmcp import FastMCP, Context
from fastmcp.server.dependencies import get_http_request

mcp = FastMCP(name="Session Aware Demo")

@mcp.tool
async def session_info(ctx: Context) -> dict:
    """利用可能な場合にセッション情報を返します。"""

    # MCPセッションが利用可能か確認します
    if ctx.request_context:
        # MCPセッションが利用可能 - MCP固有の属性にアクセスできます
        return {
            "session_id": ctx.session_id,
            "request_id": ctx.request_id,
            "has_meta": ctx.request_context.meta is not None
        }
    else:
        # MCPセッションが利用不可 - リクエストデータにHTTPヘルパーを使用します（HTTP Transportを使用している場合）
        request = get_http_request()
        return {
            "message": "MCP session not available",
            "user_agent": request.headers.get("user-agent", "Unknown")
        }
```

MCPセッションの可用性に関係なく機能するHTTPリクエストアクセス（HTTP Transportを使用する場合）については、`get_http_request()`や`get_http_headers()`などの[HTTPリクエストヘルパー](/servers/dependency-injection#http-request)を使用してください。

#### Clientメタデータ

<VersionBadge version="2.13.1" />

Clientは、`meta`パラメータを使用してリクエストにコンテキスト情報を送信できます。このメタデータは`ctx.request_context.meta`を通じてアクセスでき、すべてのMCP操作（Tool、Resource、Prompt）で利用可能です。

Clientがメタデータを提供しない場合、`meta`フィールドは`None`になります。提供された場合、メタデータは辞書アクセスではなく属性アクセス（例: `meta.user_id`）を介してアクセスできます。メタデータの構造は、リクエストを行うClientによって決定されます。

```python
@mcp.tool
def send_email(to: str, subject: str, body: str, ctx: Context) -> str:
    """リクエストに関するメタデータをロギングしながら、メールを送信します。"""

    # Clientが提供したメタデータにアクセスします
    meta = ctx.request_context.meta

    if meta:
        # Metaは属性アクセスを持つオブジェクトとしてアクセスされます
        user_id = meta.user_id if hasattr(meta, 'user_id') else None
        trace_id = meta.trace_id if hasattr(meta, 'trace_id') else None

        # ロギング、可観測性などのためにメタデータを使用します
        if trace_id:
            log_with_trace(f"Sending email for user {user_id}", trace_id)

    # メールを送信します...
    return f"Email sent to {to}"
```

<Warning>
MCPリクエストは低レベルのMCP SDKの一部であり、高度なユースケースを対象としています。ほとんどのユーザーは直接使用する必要はありません。
</Warning>
