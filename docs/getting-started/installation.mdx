## FastMCPのインストール

FastMCPのインストールと管理には、[uv](https://docs.astral.sh/uv/getting-started/installation/)の使用をお勧めします。

```bash
pip install fastmcp
```

または、uvを使用する場合：

```bash
uv add fastmcp
```

### オプションの依存関係

FastMCPは、特定の機能向けのオプション（extras）を提供しています。たとえば、バックグラウンドタスクのオプションをインストールするには、次のようにします。

```bash
pip install "fastmcp[tasks]"
```

タスクシステムの詳細については、[バックグラウンドタスク](/servers/tasks)を参照してください。

### インストールの確認

FastMCPが正しくインストールされたことを確認するには、以下のコマンドを実行します。

```bash
fastmcp version
```

次のような出力が表示されるはずです。

```bash
$ fastmcp version

FastMCP version:                           3.0.0
MCP version:                               1.25.0
Python version:                            3.12.2
Platform:            macOS-15.3.1-arm64-arm-64bit
FastMCP root path:            ~/Developer/fastmcp
```

### 依存関係のライセンス

<Info>
FastMCPはCLI機能としてCycloptsに依存しています。Cyclopts v4は推移的依存関係としてdocutilsを含んでいますが、そのライセンスは複雑であり、一部の組織ではコンプライアンス審査の対象となる可能性があります。

これが懸念される場合は、この依存関係を削除したCyclopts v5 alphaをインストールできます。

```bash
pip install "cyclopts>=5.0.0a1"
```

または、安定版のv5リリースをお待ちください。詳細については、[こちらのIssue](https://github.com/BrianPugh/cyclopts/issues/672)を参照してください。
</Info>

## アップグレード

### FastMCP 2.0からのアップグレード

破壊的変更と移行手順の完全なリストについては、[アップグレードガイド](/getting-started/upgrading/from-fastmcp-2)を参照してください。

### MCP SDKからのアップグレード

#### FastMCP 1.0からのアップグレード

`mcp` パッケージ経由でFastMCP 1.0を使用している場合（つまり、`from mcp.server.fastmcp import FastMCP` としてFastMCPをインポートしている場合）、アップグレードは簡単です。ほとんどのServerでは、インポートを1箇所変更するだけです。詳細については、[完全なアップグレードガイド](/getting-started/upgrading/from-mcp-sdk)を参照してください。

#### 低レベルServer APIからのアップグレード

`mcp` パッケージの `Server` クラスを直接使用してServerを構築した場合（`list_tools()` / `call_tool()` ハンドラーや手書きのJSON Schemaを使用している場合）、詳細な手順については[移行ガイド](/getting-started/upgrading/from-low-level-sdk)を参照してください。

## バージョニングポリシー

FastMCPはセマンティックバージョニングに従いますが、急速に進化するMCPエコシステムに合わせて実用的な調整を行っています。MCPプロトコルの最新状態を維持するために必要な場合、マイナーバージョン（例: 2.3.x から 2.4.0）で破壊的変更が発生する可能性があります。

本番環境で使用する場合は、常に正確なバージョンを固定してください。
```
fastmcp==3.0.0  # 良い例
fastmcp>=3.0.0  # 悪い例 - 破壊的変更が含まれるバージョンがインストールされる可能性があります
```

パブリックAPI、非推奨化の運用、および破壊的変更に関する考え方の詳細については、[バージョニングおよびリリースポリシー](/development/releases#versioning-policy)の全文を参照してください。
